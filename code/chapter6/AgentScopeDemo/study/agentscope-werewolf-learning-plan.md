## 三日安排

### Day 1 — 建立地图（读 + 跑）

- **学什么**：文件地图、主循环、`GameModerator`、胜负与计票  
- **做什么**：
  1. 配好 `DASHSCOPE_API_KEY`，跑一局（可接受中途 Ctrl+C）
  2. 对照日志标出：夜谈 / 查验 / 女巫 / 白天讨论 / 投票
- **小产出**：在笔记 §12 写 5 句「主循环复述」  
- **验收**：不看代码能说出夜晚三个神职阶段的顺序

### Day 2 — 编排原语（精读）

- **学什么**：`werewolf_phase` 与 `day_phase`；官方 MsgHub/Pipeline 页  
- **做什么**：
  1. 画一张「谁 observe 了谁」的箭头图（狼人夜谈 vs 白天公议）
  2. 回答：为何投票前要 `set_auto_broadcast(False)`？
- **小产出**：用自己的话写 MsgHub vs fanout 对比表（≤10 行）  
- **验收**：给一个新场景（如「警长竞选三人同时表态」）能选出应用哪种管道

### Day 3 — 约束与改造（动手）

- **学什么**：`structured_output_cn.py` + `prompt_cn.py` + `game_roles.py`  
- **做什么**：完成项目任务书中的「最小交付物」之一  
- **小产出**：改动说明 10 行 + 一次成功运行截图/日志片段  
- **验收**：改动能讲清「改了哪一层、为什么不必动另外两层」

## 风险提示

| 易卡点 | 避免方法 |
|--------|----------|
| 一上来改提示词却不懂流程 | 先完成 Day1–2 再改 Prompt |
| API 费用/耗时劝退 | 先读代码画图，跑局用 6 人且少轮数观察 |
| 教材 DialogAgent 与代码 ReActAgent 不一致 | 一律以当前源码与官方文档为准 |
| 结构化输出偶发失败 | 先理解现有 None 兜底，再考虑加强校验 |
