16.1.1 · 综合应用能力

为什么要做毕业设计？

最好的学习方式不是「再看教程」，而是动手实践——把范式、工具、记忆、协议等知识，选择性整合进一个完整项目。

  • 如何把知识应用到实际问题？
  • 如何设计一个端到端系统（而不是零散 demo）？
  • 如何处理边界情况与异常？
独立设计实现 · 熟练使用 HelloAgents · 掌握 Git/GitHub · 写清文档 · 参与开源协作 · 得到可展示作品。

16.2.1 · 好项目的标准

选题三原则

实用性

  • 解决真实问题
  • 不为技术而技术

可完成性

  • 时间与资源内可交付
  • 先 MVP，再扩展

可展示性

  • 清晰体现你的技术能力
  • 别人能跑通、看懂
小创意也值得收录。不必追求「颠覆行业」——完整、可运行、自己动手，就是好毕业设计。

16.4.1 · 项目门面

README 应写什么？

简介 · 解决什么问题 / 特色 / 场景
核心功能 · checklist（已实现打 ✅）
技术栈 · HelloAgents 范式、工具、API
快速开始 · 环境 · 安装 · .env · 运行
使用示例 · 代码 + 结果路径

16.4.1 · 可粘贴改写

README 最小骨架

16.4.6 · 避坑

常见翻车点

  1. 先堆 Prompt、后补工具 → 主路径不稳；先工具可测再接 Agent。
  2. README 最后才写 → 易漏步骤；第一天写「快速开始」空壳。
  3. 密钥写进 Notebook 并 push → 立即轮换；改用 .env。
  4. 演示依赖私有数据 → 换成可公开小样例。
  5. 功能贪多 → 一条主路径胜过五个半成品。

16.6 · jjyaoao-CodeReviewAgent

示例：智能代码审查助手

作者

@jjyaoao

路径：Co-creation-projects/jjyaoao-CodeReviewAgent/

结构

最小可运行集

README · requirements · main.ipynb · .env.example · data/ · outputs/

技术

SimpleAgent + ToolRegistry

AST 结构分析 + PEP8 风格检查 + LLM 深度建议

产出

Markdown 报告

写入 outputs/review_report.md

别担心作品「太小」。 自己动手、能跑通、写清楚，就值得收录。

CodeAnalysisTool · StyleCheckTool

自定义工具怎么拆？

CodeAnalysisTool

  • 用 ast.parse 解析代码
  • 统计函数/类/行数
  • 语法错误友好返回

StyleCheckTool

  • 行宽 > 79 提示
  • 缩进是否 4 空格层级
  • 无问题则返回「符合 PEP 8」
工具做「可计算、可验证」的事；LLM 做「语义理解与建议」。二者分工，才是 Agent 项目的味道。

注册表 · 系统提示 · 运行

从工具到审查报告

片段导读 · 完整见原书 16.6

装配代码长什么样

tool_registry = ToolRegistry() tool_registry.register_tool(CodeAnalysisTool()) tool_registry.register_tool(StyleCheckTool()) llm = HelloAgentsLLM() agent = SimpleAgent( name="代码审查助手", llm=llm, system_prompt=system_prompt, # 要求先调工具再写 Markdown 报告 tool_registry=tool_registry ) sample_code = open("data/sample_code.py", encoding="utf-8").read() review_result = agent.run(f"请审查以下Python代码:\n\n```python\n{sample_code}\n```") open("outputs/review_report.md", "w", encoding="utf-8").write(review_result)
