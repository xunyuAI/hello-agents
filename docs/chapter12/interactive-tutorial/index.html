软件测试像「断言返回 200」；智能体评估更像「作文评分」——同一题可有多种正确写法，还要看语义与结构。

12.1.1 · 与传统测试不同

智能体评估的三大挑战

① 输出不确定性

同一问题可有多个正确答案，很难用简单对错判断。解决思路：语义匹配、AST、归一化、LLM Judge。

② 评估标准多样性

工具调用看函数签名；问答看语义；协作看通信效率。解决思路：按任务选基准与指标族。

③ 评估成本高昂

每次评估大量 API 调用。解决思路：小样本冒烟 → 中等规模 → 全量；分层评估策略。

学术界/工业界用标准化 Benchmark：统一数据集 + 指标 + 评分方法，保证可比性。

12.2.1 · JSON 样本字段

BFCL 样本长什么样

{ "id": "simple_001", "question": "What's the weather like in Beijing today?", "function": [{ "name": "get_weather", "parameters": { ... } }], "ground_truth": [{ "name": "get_weather", "arguments": { "location": "Beijing" } }] }
  • question：自然语言请求
  • function：可用函数签名与描述
  • ground_truth：期望的函数调用
获取：推荐 clone Gorilla 仓库的 bfcl_eval/data/；再用 BFCLDataset 合并 ground truth。

12.2.1 · 核心算法

为什么不用字符串全等？

AST 匹配：把函数调用解析成语法树，比较结构与语义等价。

算匹配成功

  • 参数顺序不同
  • 2+3 ≡ 5
  • 引号风格不同

算匹配失败

  • 函数名错误
  • 参数值错误
  • 多函数数量不对
# 顺序不同 → ✅ get_weather(city="Beijing", unit="celsius") get_weather(unit="celsius", city="Beijing") # 函数名错 → ❌ get_temperature(...) vs get_weather(...)

12.2.1 · Accuracy 族

如何读 BFCL 分数

  • Accuracy / AST Match Rate：匹配成功样本占比
  • Category-wise Accuracy：simple / multiple / parallel… 各自准确率
  • Weighted Accuracy：按类别难度加权
  • Error Rate：1 − Accuracy
simple=0.95, multiple=0.82, parallel=0.68 weighted = (0.95+0.82+0.68)/3 ≈ 0.817
1.0 全对；0.8 表示约 80% 样本正确。先看总体，再拆类别找薄弱点。

12.3.1 · Quasi Exact Match

先归一化，再精确比

数字

  • $1,234.56 → 1234.56
  • 去单位与千分位

字符串

  • 小写、去 the/a/an
  • 去多余空格与末尾标点

列表

  • 拆分 → 归一化 → 排序
  • Paris, London, Berlin → 字母序

匹配函数：归一化后相等则为 1，否则 0。

12.3.1 · 读懂衰减

Exact Match 与难度下降率

  • Exact Match Rate：准精确匹配成功比例
  • Level-wise Accuracy：L1 / L2 / L3 各自准确率
  • Drop Rate：(Acc_ℓ − Acc_ℓ+1) / Acc_ℓ —— 难度升高时掉多少
  • Avg Steps：正确样本平均推理步数
# 示例：整体 70%；L1=100%, L2=67%, L3=50% Drop 1→2 = 33%；Drop 2→3 = 25%
下降率越大，说明复杂任务能力衰减越明显——这是找能力边界的好信号。

12.4 · AIME 风格题

为何评估「生成的数据」

训练/测试数据质量决定上限。以 AIME（答案 0–999 整数、多步推理）为例，三条互补方法：

LLM Judge

四维绝对分：正确/清晰/难度/完整

Win Rate

生成题 vs 真题成对对比

人工验证

Gradio 界面打分与状态标注

生成 → LLM Judge → Win Rate → 综合报告 →（可选）人工验证。

图 12.5 数据生成质量评估流程

12.4.1 / 12.4.4 · 多维打分

用模型当评委

  • 正确性 · 清晰度 · 难度匹配 · 完整性（各 1–5）
  • Average Score：四维均值再对样本平均
  • Pass Rate：均分 ≥ 3.5 的比例
  • Excellent Rate：均分 ≥ 4.5 的比例
LLMJudgeTool(llm).run({ "generated_data_path": "...", "reference_year": 2025, "judge_model": "gpt-4o" })
优势：快、一致、可给改进建议；风险：风格偏见、对长度敏感——故需 Win Rate / 人工互补。

12.4.1 / 12.4.5 · 相对比较

抽取生成题与 AIME 真题配对 → 比较严谨性/清晰度/难度/完整性 → 汇总胜率。
