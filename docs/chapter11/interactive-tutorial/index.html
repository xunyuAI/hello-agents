11.1 · 问题驱动

三个绕不开的问题

前面章节已实现多种智能体范式与通信协议。任务一复杂，你会自然问：

  1. 如何让智能体具备更强推理？
  2. 如何让智能体更好地使用工具？
  3. 如何让智能体能够自我改进？

监督学习像「照着标准答案抄」——抄得再像，也很难超越题解本。强化学习像「做题后对答案」——同一题尝试多条路径，奖励正确路径。

Agentic RL：把 LLM 当作可学习策略，嵌进感知–决策–执行循环，用奖励优化多步任务表现。

11.1.1 · 从强化学习到 Agentic RL

鸭子生蛋题：五元组怎么套

经典题：每天 16 蛋，早餐吃 3，烤松饼用 4，剩蛋卖 $2——日入多少？需两步：剩余 9，收入 18。

RL 概念映射
智能体基于 LLM 的推理系统
环境数学问题 + 验证系统
状态问题描述 + 已有推理步骤
行动生成下一步推理或最终答案
奖励答案正确 +1，错误 0
监督学习的三个局限
  • 数据天花板：只能模仿标注，难超越人类题解。
  • 无探索：被动学给定路径，不会试错。
  • 难优化长期目标：多步中间过程缺少精确监督信号。

11.1.2 · LLM 训练全景

预训练：学会「下一个词」

目标是学语言规律与世界知识。任务是因果语言建模（Next Token Prediction）：

L_pretrain = - Σ log P(x_t | x_1…x_{t-1}; θ)
  • 数据：TB 级文本；无监督/自监督
  • 学到：语法、语义、事实、基础推理
  • 局限：只会续写，不懂「听从指令 / 有帮助无害诚实」

11.1.2 · SFT → RM → RL

从语言模型到对话助手

① SFT

  • (prompt, completion) 对
  • L = -Σ log P(y|x)
  • 学格式与基本能力
  • 数据少、见效快

② 奖励建模 RM

  • chosen vs rejected
  • 学人类偏好分数 r_φ
  • L = -E[log σ(r_w−r_l)]

③ RL 微调

  • 经典：PPO
  • J = E[r] − β KL(π||π_ref)
  • 最大化奖励且不漂太远
RLHF vs RLAIF

RLHF：人类标注偏好，贵。RLAIF：用强 AI 打分排序，成本大幅下降，效果可接近甚至超过 RLHF。

11.1.3 · 范式分水岭

单轮偏好优化 → 多步序贯决策

PBRFT

  • T=1，s₀=prompt
  • 行动：生成整段回答 y
  • R = r_φ(s₀, y)
  • 思维：「更好的单个回答」

Agentic RL

  • T≫1，s_t=(prompt, o₁…o_t)
  • 行动：思考 / 工具 / 环境操作
  • R = Σ γᵗ r(s_t, a_t)
  • 思维：「完成复杂任务」

例子：分析 GitHub 仓库——调 API(+0.1)→读代码(+0.1)→分析(+0.2)→写报告(+0.6)=累计 1.0。

11.2.2 · 核心

奖励定义「什么是好」

目标：最大化累积回报 J(θ)=E[Σ γᵗ r]。数学任务可简化为 r(q,a)=f(a,a*)。

  • 好奖励：成功标准清晰、有梯度信号、方差可控、可组合
  • 坏奖励：过于稀疏、可被欺骗、目标互相打架、方差爆炸
MathRewardFunction（可设 tolerance）· create_*_reward() 便捷工厂

Accuracy · Length · Step · 表 11.4

公式与防作弊细节

AccuracyReward · r=1/0

提取 Final Answer / #### / 末位数字；数值容差。简单但稀疏——错一点也是 0。

LengthPenalty · r_acc − α·max(0,l−l_t)

α 默认 0.001。仅答案正确时惩罚长度，否则短错误答案会被鼓励。

StepReward · r_acc + β·s

β 默认 0.1；检测 Step N / 换行。仅正确时加分，防「假步骤刷分」。

reward_type场景
accuracy有标准答案的任务起步
length_penalty控成本、防啰嗦
step教育/可解释推理
combinedGRPO 完整训练时多目标平衡

11.2.2–11.2.3

组合权重与注册扩展

# 三者：r = r_acc − α·max(0,l−lt) + β·s "reward_type": "combined", "reward_config": {"components": [ {"type": "accuracy", "weight": 1.0}, {"type": "length_penalty", "weight": 0.5, "target_length": 200}, {"type": "step", "weight": 0.3, "step_bonus": 0.1} ]} def custom_reward(completions, **kwargs): # kwargs 常含 ground_truth；返回 List[float] ...
注意：create_reward 常只配单一类型；组合走训练配置。答案抽取失败 → 全 0 → 训练无信号。

11.3.1

没有格式，奖励就是噪声

  • 预训练输出自由文本，难抽 Final Answer
  • SFT 教会 Step / Final Answer 结构
  • 提供可评估的初始策略，缩小 RL 搜索空间

跳过 SFT 直接 RL → 答案抽取失败 → 奖励全 0 → 训练假死。SFT 是地基，GRPO 是上层建筑。

11.3.2 · 表 11.5

ΔW = BA，少参数撬大模型

冻结原权重 W，只训低秩矩阵 B、A（秩 r≪min(d,k)）。前向：h = Wx + BAx；常缩放 α/r。

  • 参数量：全量 d×k → LoRA r(d+k)（例 4096²、r=8 ≈ 256× 减少）
  • 超参：r=4–64（默认 8）；alpha≈2×rank；target：q/k/v/o_proj
  • 权衡：显存↓速度↑，效果通常略逊全量

选 LoRA

  • 单卡/显存紧
  • 教学与快速迭代
  • 多任务适配器切换

选全量

  • 算力充足
  • 追求极限精度
  • 分布偏移极大

11.4.1 · 表 11.6

为何 LLM 更爱 GRPO

PPO 痛点

  • 需要 Value Model
  • 四模型：Policy/Ref/Value/Reward
  • 不稳、易奖励崩塌
  • 显存与工程重

GRPO 优势

  • 无需 Value Model
  • Policy + Reference
  • 组内相对奖励降方差
  • 更稳、更省显存

数学直觉

用「比同组更好」代替优势函数

PPO: A = Q − V（需 Value） GRPO: J ≈ E[ (π_θ/π_ref) · (r − r̄_group) ] − β · KL(π_θ || π_ref)

例：组奖励 [1, 1, 0, 0.8]，均值 0.7 → 相对 [+0.3, +0.3, −0.7, +0.1]。正确且更好的样本被强化，差的被抑制。

KL：β 即 kl_coef，建议 0.05–0.1。太大学不动，太小策略漂飞。

11.4.2 · GRPOTrainerWrapper

从 SFT 权重起步

rl.run({ "action": "train", "algorithm": "grpo", "model_name": "./models/sft_full", "output_dir": "./models/grpo_full", "num_epochs": 3, "batch_size": 4, "learning_rate": 1e-5, "num_generations": 4, "max_new_tokens": 512, "temperature": 0.8, "kl_coef": 0.05, "clip_range": 0.2, "use_lora": True, "lora_rank": 16, "lora_alpha": 32, "reward_type": "combined" })
  • lr 通常小于 SFT（1e-5–5e-5）
  • batch_size 须能被 num_generations 整除
  • OOM：减 generations / batch / max_new_tokens

11.4.3

采样 → 打分 → 相对化 → 更新

异常诊断速查
  • 奖励不升：lr 过小 / kl 过大 / 奖励差 / SFT 基线差
  • KL > 0.5：降 lr、增 kl_coef、奖励别过激
  • 准确率升但格式崩：combined 奖励、加大 kl
