通信协议

Protocol

点击翻转

白话

双方约定「怎么打招呼、消息长什么样、出错怎么办」的规则书。没有协议，每个工具都得手写适配器。

握手

Handshake

点击翻转

白话

正式干活前的「接通电话」：建连、交换能力清单、确认版本。MCP 里常见 initialize + list_tools。

Host / Client / Server

MCP 三层

点击翻转

白话

Host是用户界面（如桌面 App）；Client负责按协议通话；Server真正干活（读文件、查库）。

Task / Artifact

A2A 核心抽象

点击翻转

白话

Task是可协商、可跟踪的协作任务；Artifact是任务产出物（草稿、报告片段）。比「调一次函数」更像项目协作。

服务发现

Discovery

点击翻转

白话

不知道谁能干这活时，先查「黄页」：按类型/能力找节点。ANP 解决「上千个 Agent 时如何找对人」。

DID

去中心化身份

点击翻转

白话

不靠中央账号系统的数字身份证。ANP 用 DID + 签名验证「你是不是你声称的那个 Agent」。

MCP ≈ USB-C（插上就能用工具）；A2A ≈ 同事对讲机（点对点派活）；ANP ≈ 互联网黄页 + 路由（在大网里找服务）。

10.1.1 · 三个根本限制

单体 Agent 的天花板

即便 ReAct + 计算器 + 搜索已经很好用，复杂系统仍会撞上三堵墙。

工具集成困境

每接一个 GitHub / 数据库 / 天气 API，都要手写 Tool 类：HTTP、鉴权、错误处理重复一遍；别人的工具也难直接复用。

能力扩展瓶颈

能力被「预先 add_tool 的集合」锁死，运行时很难动态发现新服务。

协作缺失

研究员 + 撰写员 + 编辑这类任务，只能靠人工编排脚本硬串——没有标准「Agent 对 Agent」对话层。

标准化接口 · 互操作性 · 动态发现 · 可扩展性——像 TCP/IP 让设备互通，而不是为每对设备写专用线。
# 有协议后：连上 MCP 服务器即获得工具包 from hello_agents.tools import MCPTool github_mcp = MCPTool(server_command=["npx", "-y", "@modelcontextprotocol/server-github"]) agent.add_tool(github_mcp)

Host 宿主

10.2.1 · 表 10.3 · 互补不是替代

已经有 Function Calling，为何还要 MCP？

Function Calling

  • 模型能力：何时调、填什么参
  • 各厂商 schema 格式不同
  • 工具实现多半自己写
  • 换模型常需改适配代码

  • 可复用社区 Server
  • 与模型厂商解耦
COMPLEMENTARY
Function Calling = 「你会打电话」；MCP = 「全球统一电话标准」。会打电话不等于插座制式统一。

10.2.4 · MCPTool

一个 MCPTool → 展开成多个工具

把 MCP 服务器挂到 Agent 时，HelloAgents 会把服务器上的工具展开为 Agent 可直接调用的独立工具。

from hello_agents import SimpleAgent, HelloAgentsLLM from hello_agents.tools import MCPTool agent = SimpleAgent(name="助手", llm=HelloAgentsLLM()) mcp_tool = MCPTool(name="calculator") # 内置演示服务器 agent.add_tool(mcp_tool) # ✅ 已展开为多个独立工具，如 add / multiply … # 社区文件系统 fs = MCPTool(name="fs", server_command=["npx","-y","@modelcontextprotocol/server-filesystem","."]) agent.add_tool(fs) # → fs_read_file 等，前缀防冲突
每个 MCPTool 务必设不同 name 作前缀，避免 read_file 撞名。

10.4.2 · API 心智

ANPDiscovery 最小闭环

from hello_agents.protocols import ANPDiscovery, register_service, discover_service, ANPNetwork discovery = ANPDiscovery() register_service(discovery=discovery, service_id="nlp_agent_1", service_name="NLP专家A", service_type="nlp", capabilities=["text_analysis","ner"], endpoint="http://localhost:8001", metadata={"load": 0.3, "price": 0.01}) nlp = discover_service(discovery, service_type="nlp") best = min(nlp, key=lambda s: s.metadata.get("load", 1.0)) network = ANPNetwork(network_id="ai_cluster") for s in discovery.list_all_services(): network.add_node(s.service_id, s.endpoint) network.connect_nodes("nlp_agent_1", "nlp_agent_2") print(network.get_network_stats())

10.4.3 · 实战案例心智

任务调度器 + ANPTool

注册多个 compute 节点（带 load / cpu / gpu 元数据）→ 调度 Agent 挂上 ANPTool → 用自然语言描述任务，让模型选出合适节点。

负载均衡一句话

best = min(servers, key=lambda s: s.metadata.get("load", 1.0))，请求后可模拟 load += 0.1。

ANP 找节点 → A2A 派任务 → MCP 让节点调用工具：三种协议可以叠在同一系统里。
