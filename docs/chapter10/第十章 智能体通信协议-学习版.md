# 第十章 智能体通信协议

前面几章，我们已经能搭出「会推理、会调工具、有记忆、会拼上下文」的**单体智能体**。但只要任务再复杂一点，你很快会撞上三堵墙：

1. 每接一个外部服务（GitHub、数据库、天气…）都要手写一套 Tool；
2. 能力被写死在启动时注册的那几个工具里，运行时很难「发现」新服务；
3. 研究员 + 撰写员 + 编辑这类多角色协作，只能靠你在 Python 里硬编码流水线。

这一章要补的，就是智能体通向外部世界、通向其他智能体、通向大规模网络的**通信协议层**：

| 协议 | 全称 | 一句话 |
|------|------|--------|
| **MCP** | Model Context Protocol | Agent ↔ 工具/资源的「USB-C」 |
| **A2A** | Agent-to-Agent Protocol | Agent ↔ Agent 的点对点协作 |
| **ANP** | Agent Network Protocol | 大规模网络里的发现与路由 |

在 HelloAgents 里，这三者都被封装成标准 **Tool**（`MCPTool` / `A2ATool` / `ANPTool`），所以你学过的 `SimpleAgent`、`ReActAgent` 可以「即插即用」。

## 读这一章之前，先建立心智模型

### 一个生活比喻

| 现实世界 | 协议对应 |
|---------|---------|
| 统一的 USB-C 接口插键盘/硬盘/显示器 | **MCP**：统一插各种工具 Server |

| 公司黄页 / 服务注册中心：找「谁能修打印机」 | **ANP**：在大网里发现与路由服务 |

再记一个容易混的点：

- **Function Calling（函数调用）**：模型「会不会打电话」——何时拨号、说什么参数。
- **MCP**：全球统一的「电话网标准」——怎么描述工具、怎么连上工具。

二者**互补**，不是二选一。

## 10.1 智能体通信协议基础

### 10.1.1 为何需要通信协议

回顾第七章风格的用法：给 `ReActAgent` 挂上 `CalculatorTool`、`SearchTool`，它能独立完成「搜新闻 + 算市值」这类任务。但研究助手一旦要同时碰 GitHub、数据库、天气，传统写法会变成：

```python
class GitHubTool(BaseTool): ...
class DatabaseTool(BaseTool): ...
class WeatherTool(BaseTool): ...
# 每个都要自己处理 HTTP、鉴权、错误、解析
```

**三个根本限制：**

1. **工具集成困境**：重复造适配器；API 一变处处改；别人的工具很难直接复用。  
2. **能力扩展瓶颈**：能力锁死在预注册工具集；难以运行时发现新服务。  
3. **协作缺失**：多专业 Agent 只能靠手动编排，没有标准的任务/状态协商。

**协议的核心价值**：提供标准化接口——像 TCP/IP 让不同设备互通，而不必为每种设备写专用通信代码。

有了 MCP，上面可以收敛成「连服务器，拿工具」：

```python
from hello_agents.tools import MCPTool

mcp_tool = MCPTool()  # 内置演示
github_mcp = MCPTool(server_command=["npx", "-y", "@modelcontextprotocol/server-github"])
agent.add_tool(mcp_tool)
agent.add_tool(github_mcp)
```

收益可以记四个词：**标准化 · 互操作 · 动态发现 · 可扩展**。

### 10.1.2 三种协议设计理念比较

#### （1）MCP：智能体与工具的桥梁

- 提出方：Anthropic。  
- 理念：标准化 Agent 访问外部工具/资源的方式；强调**上下文共享**（不只 RPC）。  
- 例：访问代码仓库时，Server 除了文件内容，还可提供结构、依赖、提交历史等上下文。  
- 见图 10.1（原书）。

#### （2）A2A：智能体间的对话

- 提出方：Google 相关开源方向。  
- 理念：**点对点**协作；每个 Agent 既是服务者也是消费者。  
- 避免中心协调器成为单点故障与性能瓶颈。  
- 见图 10.2。

#### （3）ANP：智能体网络的基础设施

- 社区概念框架（生态仍早期）。  
- 理念：大规模网络中的**服务注册、发现、路由**。  
- HelloAgents 提供轻量**概念模拟**便于学习；官方亦有 [AgentConnect](https://github.com/agent-network-protocol/AgentConnect) 等实现。  
- 见图 10.3、表 10.1。

#### （4）如何选择？

| 你的需求 | 优先协议 |
|---------|---------|
| 访问文件 / DB / API / 第三方服务 | **MCP** |
| 多个智能体互相协作完成任务 | **A2A** |
| 构建大规模、可动态扩展的 Agent 生态 | **ANP** |

当前阶段：MCP 生态相对成熟；更推荐选择有大厂/官方背书、维护活跃的 MCP 工具。三者可以**组合**使用（客服系统：MCP 查库 + A2A 专家协作 + ANP 做节点发现）。

### 10.1.3 HelloAgents 通信协议架构设计

设计目标：**最简单的使用方式 + 足够灵活应对复杂场景**。

三层（自下而上，图 10.4）：

1. **协议实现层**  
   - MCP：基于 FastMCP（client/server）  
   - A2A：基于 `a2a-sdk`（可选依赖）  
   - ANP：自研轻量概念实现  
2. **工具封装层**  
   - `MCPTool` / `A2ATool` / `ANPTool` 继承 `BaseTool`，统一 `run()`  
3. **智能体集成层**  
   - 任意 Agent 经 Tool System 使用，无需关心底层协议细节  

模块树（学习导航用）：

```
hello_agents/
├── protocols/
│   ├── mcp/     # client.py · server.py · utils.py
│   ├── a2a/     # implementation.py
│   └── anp/     # implementation.py
└── tools/builtin/
    └── protocol_tools.py   # 三个 Tool 包装器
```

### 10.1.4 本章学习目标与快速体验

**学习目标**：能在自己的项目里**应用**这三种协议；协议早期阶段，少造轮子、多用生态。

**30 秒体验：**

```python
from hello_agents.tools import MCPTool, A2ATool, ANPTool

# 1) MCP：内置演示服务器（Memory 传输）
mcp_tool = MCPTool()

    "action": "call_tool",
    "tool_name": "add",
    "arguments": {"a": 10, "b": 20}
}))  # 30.0

# 2) ANP：注册并发现
anp_tool = ANPTool()
anp_tool.run({
    "action": "register_service",
    "service_id": "calculator",
    "service_type": "math",
    "endpoint": "http://localhost:8080"
})
print(anp_tool.run({"action": "discover_services"}))

# 3) A2A：指向已启动的服务端
a2a_tool = A2ATool("http://localhost:5000")
```

## 10.2 MCP 协议实战

### 10.2.1 MCP 协议概念介绍

#### （1）智能体的「USB-C」

Agent 可能同时要：读本地文件、查 PostgreSQL、搜 GitHub、发 Slack、访问 Drive。传统适配器 + 各家 Function Calling schema 差异，维护成本极高。MCP 统一「插工具」的方式：换模型不必重写整套胶水。

#### （2）Host / Client / Server（图 10.5）

以 Claude Desktop 问「桌面上有哪些文档？」为例：

1. **Host**：用户界面与对话流程（Claude Desktop）。  
2. **Client**：模型决定要文件信息时，建立与 Server 的连接。  
3. **Server**：文件系统 Server 扫描桌面并返回列表。  

完整链路：用户问题 → Host → 模型分析 → Client → Server 执行 → 结果回模型 → 回答显示。

**关注点分离**：多数开发者主要写 Server，不必重写 Host/Client。

#### （3）三大核心能力（表 10.2）

| 能力 | 性质 | 做什么 |
|------|------|--------|
| **Tools** | 主动 | 执行操作（读文件、搜仓库…） |
| **Resources** | 被动 | 按 URI 提供数据/上下文 |
| **Prompts** | 指导 | 预置提示模板（如 code_review） |

#### （4）工具选择工作流（图 10.6）

1. `list_tools()` 发现工具描述与参数 schema  
2. Client 把工具列表写入系统提示  
3. LLM 决定是否调用、调用哪个、填什么参  
4. 经 Server 执行  
5. 结果回灌，生成最终回答  

**关键：**工具描述写得越清楚，模型用得越准。

#### （5）与 Function Calling 的差异（表 10.3）

**FC 路径（示意）：**为 OpenAI / Claude 各写一份 tools schema → 自己实现 `search_github` → 分别解析 `tool_calls` / `tool_use`。

**MCP 路径（示意）：**

```python
from hello_agents.protocols import MCPClient

github_client = MCPClient(["npx", "-y", "@modelcontextprotocol/server-github"])
async with github_client:
    tools = await github_client.list_tools()
    result = await github_client.call_tool("search_repositories", {"query": "AI agents"})
```

记住类比：**FC = 学会打电话；MCP = 电话网标准。**

### 10.2.2 使用 MCP 客户端

HelloAgents 基于 FastMCP 2.0，提供异步/同步 API；多数场景推荐异步。

**（1）连接（Stdio 最常用）**

```python
client = MCPClient(["npx", "-y", "@modelcontextprotocol/server-filesystem", "."])
async with client:
    tools = await client.list_tools()
```

也可：`MCPClient(["python", "my_mcp_server.py"])`。

**（2）发现工具**：遍历 `name` / `description` / `inputSchema.properties`。  
**（3）调用工具**：`call_tool(name, args)`；对可能失败的路径加 `try/except`。  
**（4）资源**：`list_resources` / `read_resource(uri)`。  
**（5）提示模板**：`list_prompts` / `get_prompt(name, args)`。  

**（6）MCPTool + GitHub（同步封装）**

```python
# 需设置 GITHUB_PERSONAL_ACCESS_TOKEN
from hello_agents.tools import MCPTool

github_tool = MCPTool(server_command=["npx", "-y", "@modelcontextprotocol/server-github"])
print(github_tool.run({"action": "list_tools"}))
print(github_tool.run({
    "action": "call_tool",
    "tool_name": "search_repositories",
    "arguments": {"query": "AI agents language:python", "page": 1, "perPage": 3}
}))
```

### 10.2.3 MCP 传输方式详解

MCP **传输层无关**（Transport Agnostic）。HelloAgents 支持五种方式（表 10.4）：

| 方式 | 典型场景 |
|------|---------|
| **Memory** | 单测、快速原型：`MCPTool()` 无参 |
| **Stdio** | 本地开发、`npx` 社区包、自定义 `python server.py` |
| **HTTP** | 远程服务、微服务生产 |
| **SSE** | 实时/流式长连接 |
| **StreamableHTTP** | 双向流式 HTTP |

实践建议：`MCPTool` 主力 Memory/Stdio；远程 HTTP/SSE 用底层 `MCPClient` 并指定 `transport_type`。

### 10.2.4 在智能体中使用 MCP 工具

#### （1）自动展开

`agent.add_tool(MCPTool(name="calculator"))` 时，框架会把 Server 上的工具展开为带前缀的独立工具，例如：

- `calculator_add` / `_subtract` / `_multiply` / `_divide` / `_greet` / `_get_system_info`

Agent 侧调用形如 `[TOOL_CALL:calculator_multiply:a=25,b=16]`，系统负责类型转换与 MCP 调用。

连接外部 Server：

```python
fs_tool = MCPTool(
    name="filesystem",
    description="访问本地文件系统",
    server_command=["npx", "-y", "@modelcontextprotocol/server-filesystem", "."]
)
agent.add_tool(fs_tool)
```

**多 Server 必须用不同 `name` 作前缀**，否则展开名冲突（`fs_read_file` vs `gh_…`）。

#### （2）展开原理（心智模型）

1. 连接 Server → `list_tools`  
2. 为每个工具建包装器并注册到 Agent  
3. Agent 选中包装器 → 转成 `{"action":"call_tool", ...}` → 调 Server → 回传结果  

#### （3）实战：智能文档助手（双 Agent 编排）

- **Agent1 GitHub 搜索专家**：挂 `MCPTool(name="gh", …github)`，返回结构化搜索结果。  
- **Agent2 文档生成专家**：根据搜索结果生成 Markdown 报告（可挂 filesystem）。  
- 应用层把 Agent1 输出拼进 Agent2 的 prompt，最后写入 `report.md`。  

注意：这是**应用层多 Agent 编排**；协议层的 A2A 是后文主题。

## 10.3 A2A 协议实战

### 10.3.1 协议设计动机

MCP 解决 Agent↔工具；A2A 解决 **Agent↔Agent**（通信、委托、协商、同步状态）。

**中心协调器（星型）的问题：**单点故障 · 性能瓶颈 · 扩展要改中心逻辑。  
**A2A：**点对点网状；核心抽象是 **Task（任务）** 与 **Artifact（工件）**（表 10.7）。

任务生命周期（图 10.7）：创建 → 协商 → 代理 → 执行中 → 完成 / 失败……便于进度跟踪与异常处理。

请求生命周期常见四步（图 10.8）：**代理发现 → 身份验证 → 消息 API → 流式消息 API**。

### 10.3.2 使用 A2A 协议实战

生态多为止样例代码；HelloAgents 基于 `a2a-sdk` 做可教学封装。先检查 `A2A_AVAILABLE`，否则 `pip install a2a-sdk`。

**创建计算器 Agent（示意）：**

```python
from hello_agents.protocols.a2a.implementation import A2AServer, A2A_AVAILABLE

calculator = A2AServer(
    name="calculator-agent",
    description="专业的数学计算智能体",
    capabilities={"math": ["addition", "multiplication"]}
)

@calculator.skill("add")
def add_numbers(query: str) -> str:
    ...
```

本地可用 `calculator.skills["add"](query)` 先测技能；再谈网络暴露。自定义 Agent 同理：`A2AServer` + 多个 `@skill`。

### 10.3.3 使用 HelloAgents A2A 工具

**（1）服务端：**`A2AServer` + `@skill`，后台线程 `run(host="localhost", port=5000)`。  
**（2）客户端：**`A2AClient(url).execute_skill("research", "research …")`。  
**（3）Agent 网络：**研究员:5000、撰写员:5001、编辑:5002，编排函数串联 research → write → edit。

### 10.3.4 在智能体中使用 A2A 工具

**A2ATool 包装器：**把远程 Agent 挂到协调者 `SimpleAgent`：

```python
from hello_agents.tools import A2ATool

researcher_tool = A2ATool(
    name="researcher",
    description="研究员Agent，可以搜索和分析资料",
    agent_url="http://localhost:5000"
)
coordinator.add_tool(researcher_tool)
```

**智能客服案例：**接待员（SimpleAgent）分析问题类型；技术专家 / 销售顾问（A2AServer）提供 `answer` skill；接待员挂两个 `A2ATool` 转发。

**高级扩展点：**协商（`propose` / `negotiate`）、反提案（如 deadline 不够则还价）——为冲突解决留协议空间。

## 10.4 ANP 协议实战

### 10.4.1 协议目标

当网络里有大量功能各异的 Agent 时，要回答：

1. **服务发现**：谁能处理这个任务？  
2. **智能路由**：多个候选时选负载低还是成本低的？  
3. **动态扩展**：新节点如何被别人发现？  

核心概念见原书表 10.8。整体流程（图 10.9，参考官方入门指南）：

1. **发现与匹配**：发现服务爬取 `.well-known/agent-descriptions` 建索引，按语义/能力匹配。  
2. **DID 身份验证**：私钥签名 ↔ 公钥验签，建立可信通信。  
3. **标准化服务执行**：按统一接口交换数据或调用服务。  

去中心化信任 + 标准描述 → 无需中央协调也能组网。

### 10.4.2 使用 ANP 服务发现

```python
from hello_agents.protocols import (
    ANPDiscovery, register_service, discover_service, ANPNetwork
)

discovery = ANPDiscovery()
register_service(
    discovery=discovery,
    service_id="nlp_agent_1",
    service_name="NLP处理专家A",
    service_type="nlp",
    capabilities=["text_analysis", "ner"],
    endpoint="http://localhost:8001",
    metadata={"load": 0.3, "price": 0.01}
)

nlp_services = discover_service(discovery, service_type="nlp")
best = min(nlp_services, key=lambda s: s.metadata.get("load", 1.0))

network = ANPNetwork(network_id="ai_cluster")
for s in discovery.list_all_services():
    network.add_node(s.service_id, s.endpoint)
```

`metadata`（load / cpu / gpu / price…）是路由决策的特征，不是装饰字段。

### 10.4.3 实战案例

**分布式任务调度：**注册多个 `compute` 节点 → `SimpleAgent` + `ANPTool` 作调度器 → 按「需要 GPU / 高内存 / 轻量分析」等描述选节点。

**负载均衡：**同类型 API 服务池，每次取 `load` 最小者，分配后模拟 `load += 0.1`。

**和 MCP/A2A 的边界：**ANP 解决「先找到谁」；真正干活仍可用 MCP（工具）或 A2A（对话）。

## 10.5 构建自定义 MCP 服务器

### 10.5.1 创建你的第一个 MCP 服务器

**为何自建？**封装业务逻辑 · 访问私有数据 · 性能优化 · 功能定制（专有算法/硬件）。

**天气查询教学案例（骨架）：**

```python
from hello_agents.protocols import MCPServer

weather_server = MCPServer(name="weather-server", description="真实天气查询服务")

def get_weather(city: str) -> str:
    """获取指定城市的当前天气"""  # 内部可调 wttr.in + 中文城市映射
    ...

def list_supported_cities() -> str: ...
def get_server_info() -> str: ...

weather_server.add_tool(get_weather)
weather_server.add_tool(list_supported_cities)
weather_server.add_tool(get_server_info)

if __name__ == "__main__":
    weather_server.run()
```

**测试：**`MCPClient(["python", "14_weather_mcp_server.py"])` 依次调三个工具。  
**接入 Agent：**`MCPTool(server_command=["python", server_script])`，观察自动展开为 `mcp_get_weather` 等。

### 10.5.2 上传 MCP 服务器

[Smithery](https://smithery.ai/) ≈ MCP 的 PyPI/npm：搜索、一键安装、统计、更新。

推荐目录结构：


## 10.6 本章总结

| 协议 | 定位 | 适合 |
|------|------|------|
| MCP | Agent-工具桥梁 | 增强单体能力 |
| A2A | Agent 对话与任务协商 | 小团队紧密协作 |
| ANP | 发现 / 路由 / 负载 | 大规模开放网络 |

统一接入：

```python
from hello_agents.tools import MCPTool, A2ATool, ANPTool
agent.add_tool(MCPTool(...))
agent.add_tool(A2ATool(...))
agent.add_tool(ANPTool(...))
```

**实战经验：**优先成熟社区 MCP；小规模协作偏 A2A；大规模发现偏 ANP；三者可组合。

**建议下一步：**

1. 动手：自建 MCP Server、多 Agent 协作、三协议组合小项目。  
2. 精读官方文档：  
   - https://modelcontextprotocol.io  
   - https://a2a-protocol.org/latest/  
   - https://agent-network-protocol.com/guide/  
3. 参与社区：贡献 Server、分享案例、在 Issue 讨论。

## 习题导读（新手向）

> 原书习题偏开放题，这里给出「怎么下手」的提示，不等于标准答案。

1. **选型与组合**  
   - 用自己的话解释：为何 MCP 强调上下文共享、A2A 强调对话协作、ANP 强调网络拓扑。  
   - 智能客服三功能（查库 / 专家协作 / 大规模并发发现）分别选哪一协议。  
   - 画一张「MCP+A2A+ANP」架构草图，标注每层职责。

2. **MCP 动手**  
   - 扩展一个「数据分析」Server：查询 + 可视化 + 报表，工具间能协作。  
   - 查阅官方文档，设计一个同时用 Tools / Resources / Prompts 的小场景。  
   - 思考 stdio 的优劣，以及如何扩展到 HTTP/WebSocket 远程 Server。

3. **A2A 扩展**  
   - 在研究团队流程中增加「审稿人」角色，画出三方消息流。  
   - 设计协商/投票消息类型，处理意见冲突。  
   - 对比 AutoGen / CAMEL：协议与框架如何共存，而非互相替代。

4. **ANP 深入**  
   - 10 节点 vs 1000 节点时拓扑如何演进。  
   - 设计综合任务类型、能力、负载的路由启发式。  
   - 关键节点故障时的检测、切换、状态恢复。

5. **安全与信任**  
   - MCP 危险工具（删文件、跑命令）如何做权限控制。  
   - A2A/ANP 敏感数据的端到端加密与身份认证。  
   - 大规模网络中的信任评分与通信策略调整。
