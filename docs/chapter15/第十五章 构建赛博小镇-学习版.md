# 第十五章 构建赛博小镇

前面章节里，HelloAgents 多半待在「终端 / API」世界里：Agent 会思考、会调工具、会记记忆。这一章把舞台换成**可走动的 2D 像素办公室**——把智能体焊进 Godot 游戏引擎，做出真正「活着」的 NPC。

你可以把本章理解成一次**全栈综合实战**：

- **大脑**：HelloAgents `SimpleAgent` + 记忆 + 好感度  
- **中枢**：FastAPI 编排状态、对话、日志  
- **身体**：Godot 场景、玩家控制、对话 UI  

目标不是背完每一行 GDScript，而是建立一张清晰的**心智地图**：一次按 `E` 之后，请求怎么走、记忆怎么取、好感怎么变、画面怎么回。

| 现实世界 | 赛博小镇 |

| 办公室里三位同事 | 张三 / 李四 / 王五三个 NPC |

| 同事有时自言自语在忙 | 批量生成的背景台词 |
| 你走过去认真谈话 | `POST /dialogue` 即时 Agent |

### 几个关键词，先抓牢

- **四层架构**：Godot 前端 → FastAPI 后端 → HelloAgents 智能体 → LLM / Qdrant / SQLite。  
- **SimpleAgent**：每 NPC 一个实例；性格写在 `system_prompt`。  
- **混合模式**：背景台词批量省钱；玩家对话即时保质。  
- **好感度**：LLM 判态度 → 加减分 → 动态改 Prompt 语气。  
- **场景（Scene）**：Godot 的「预制件」；三 NPC 是同一 `NPC.tscn` 实例化三次。  
- **信号（Signal）**：Godot 组件松耦合通信方式。

## 15.1 项目概述与架构设计

### 15.1.1 为什么要构建 AI 小镇

传统 RPG 的 NPC 多半是**对话树**：编剧写死分支，可控但难有生命力。AI NPC 的跃迁在于：

1. 任意自然语言，而不是三个按钮选项；  
2. 记得历史与关系；  
3. 每人有职业、性格、说话风格；  
4. 态度随互动变化。

**新手可以这样记：** 对话树像自动贩卖机；AI NPC 像真同事——你随便说，他按人设与记忆接话。

应用面：教育角色扮演、虚拟办公室导师、陪伴场景、传统游戏增强。教学项目里，Datawhale 办公室是一个足够小、又足够完整的沙盘。

### 15.1.2 技术架构概览

赛博小镇采用 **游戏引擎 + 后端服务** 分离：

| 层 | 技术 | 职责 |
|----|------|------|
| 前端 | Godot 4.x | 渲染、移动、NPC 显示、对话 UI |
| 后端 | FastAPI | 路由、状态、编排、日志 |
| 智能体 | HelloAgents | NPC 智能、记忆、好感计算 |
| 外部 | LLM / Qdrant / SQLite | 推理、向量、持久化 |

**一次对话的数据流（务必背熟）：**

1. 玩家靠近 NPC，按 `E`  
2. Godot `HTTPRequest` → FastAPI  
3. 取好感等级，拿到对应 Agent  
4. 检索短期 + 长期记忆，调用 LLM  
5. 更新好感度、写日志、释放 busy  
6. JSON 回包，UI 展示回复  

项目根目录逻辑上分两半：

```
Helloagents-AI-Town/
├── helloagents-ai-town/   # Godot
└── backend/               # Python
```

仓库内路径：`code/chapter15/Helloagents-AI-Town`。

### 15.1.3 快速体验：5 分钟运行项目

**环境：** Godot ≥ 4.2 · Python ≥ 3.10 · LLM API Key  

**后端：**

```bash
cd Helloagents-AI-Town/backend
pip install -r requirements.txt
cp .env.example .env   # 填写密钥
python main.py
```

成功时应看到 API 地址与 `/docs`。  

**前端：** 用 Godot 导入项目，打开 `main.tscn`，按 `F5`。WASD 移动，靠近按 `E` 对话。

**好感度去哪看？** 前端未必直接显示数值；看 `backend/logs/dialogue_YYYY-MM-DD.log` 或 `python view_logs.py`：当前分、命中记忆、Δ分、情感标签。这是「可观测性」设计：先保证后端账本清晰，再考虑做心形 UI。

## 15.2 NPC 智能体系统

### 15.2.1 基于 HelloAgents 的 SimpleAgent

每个 NPC = 一个 `SimpleAgent`：

1. 用姓名 / 职业 / 性格拼 `system_prompt`  
2. `HelloAgentsLLM()`  
3. `MemoryManager(WorkingMemory, EpisodicMemory)`  
4. 返回 Agent  

示例参数直觉：

- **WorkingMemory**：`capacity=10`，`ttl_minutes=120` → 管「刚才几句」  
- **EpisodicMemory**：按 `npc_id` 分库 / 分 collection → 管「很久以前相关话题」

### 15.2.2 NPC 角色设定与 Prompt 设计

| NPC | 职业 | 性格关键词 |
|-----|------|-----------|
| 张三 | Python 工程师 | 严谨、直接、代码质量 |
| 李四 | 产品经理 | 外向、用户视角、爱问为什么 |
| 王五 | UI 设计师 | 温和、创意、审美 |

**学习要点：** 差异几乎全在 Prompt 与配置字典；创建函数可复用。想加第四个 NPC，优先加配置，而不是复制一整套类。

### 15.2.3 记忆系统集成

对话处理推荐心智顺序：

```
近期 Working → 语义检索 Episodic → 拼 context → agent.run → add_interaction
```

- 「它是什么颜色？」→ 靠短期指代  
- 「还记得上次那个项目吗？」→ 靠长期语义检索  

这与第八章记忆理论一致，本章是**装进游戏循环**。

### 15.2.4 批量对话生成：轻负载模式

**问题：** 多 NPC / 多玩家时，每人每次都打 LLM，贵且易撞限流。  

**解法：** `NPCBatchGenerator` 一次调用生成所有 NPC 的一句话，强制 JSON：

```json
{"张三":"...","李四":"...","王五":"..."}
```

适合：进入场景时的自言自语、定时氛围更新、降本。  
**不适合：** 替代玩家一对一认真对话。

**混合模式（本章高分设计）：**

| 模式 | 时机 | 目的 |
|------|------|------|
| 批量 | 后台约每 5 分钟 | 背景台词，NPC「看起来在活」 |
| 即时 | `POST /dialogue` | 个性化、带记忆与好感 |

口诀：**远看用批量，近聊用即时。**

## 15.3 好感度系统设计

### 15.3.1 好感度等级划分

| 等级 | 分数 | 行为倾向 |
|------|------|----------|
| 陌生 | 0–20 | 礼貌疏远、回复短 |
| 熟悉 | 21–40 | 自然交流 |
| 友好 | 41–60 | 更详细、会主动问 |
| 亲密 | 61–80 | 私人话题、热情建议 |
| 挚友 | 81–100 | 无话不谈 |

分数是账本；玩家感受到的是**信息密度与语气**。后续可把高等级做成任务锁。

### 15.3.2 好感度计算逻辑

不要「每句话 +1」。本章用 LLM 做情感分析：

- 友好 → +5  
- 中立 → +2  
- 不友好 → −3  
- 解析失败 → 默认 +2  
- 最终分数 clamp 到 `[0, 100]`

`RelationshipManager` 按 `npc_id + player_name` 存独立关系。

### 15.3.3 好感度影响对话

把等级映射成一段附加系统提示，例如陌生要求「简短专业」，挚友要求「亲切真诚」。  
**工程含义：** 同一 Agent 骨架，**Prompt 随关系动态变**，比单独训练多个模型便宜得多。

## 15.4 后端服务实现

### 15.4.1 FastAPI 应用结构

`main.py` 职责清单：

- 创建 `FastAPI` 应用与 CORS  
- 组装 `NPCAgentManager` / `RelationshipManager` / `StateManager` / `DialogueLogger`  
- `startup` 初始化 NPC 与状态  
- `GET /` 健康检查  

模块化文件：`agents.py`、`relationship_manager.py`、`state_manager.py`、`logger.py`、`models.py`、`config.py`。

### 15.4.2 API 路由设计

| 接口 | 作用 |
|------|------|
| `GET /npcs/status` | 全部 NPC 状态（含背景台词等） |
| `GET /npcs/{id}/status` | 单个状态 |
| `POST /dialogue` | 核心对话 |
| `GET /affinity/{npc}/{player}` | 查好感 |

**`/dialogue` 九步（建议能默写）：**

1. 校验 NPC 存在  
2. busy → **409**  
3. 标记 busy  
4. 取当前好感等级  
5. Agent 生成回复  
6. 更新好感  
7. 写日志  
8. 返回 `DialogueResponse`  
9. `finally` 释放 busy  

busy 像厕所门锁：防止一个 NPC 同时服务两个玩家。

### 15.4.3 状态管理与日志系统

- **StateManager**：位置、busy、动作、背景台词字段  
- **DialogueLogger**：控制台 + 按日文件；记录分值、记忆命中、情感  

没有日志，好感与 Prompt 调参会变成玄学。

### 15.4.4 理解 Godot 的场景系统

- **节点（Node）**：乐高块（Sprite2D、CharacterBody2D…）  
- **场景（Scene）**：保存为 `.tscn` 的节点树，可嵌套实例化  

玩家场景示例：

```
Player (CharacterBody2D)
├─ AnimatedSprite2D
├─ CollisionShape2D
└─ Camera2D
```

三 NPC 共用一个 `NPC.tscn`：改气泡一次，全员生效；差异用导出变量（名字、id、职称）。

## 15.5 Godot 游戏场景构建

### 为什么选 Godot（选型速记）

1. **2D 成熟**：TileMap / AnimatedSprite2D / CharacterBody2D  
2. **MIT 开源**：教学友好  
3. **GDScript ≈ Python**：学习曲线平缓  
4. **HTTPRequest**：天然对接 FastAPI  

局限：重度 3D 另议；本项目像素办公室足够。

### 15.5.1 场景设计与资源组织

四个核心场景：

| 场景 | 角色 |
|------|------|
| Main | 组合背景、Player、三 NPC、UI、墙、BGM |
| Player | 移动、动画、相机、音效 |
| NPC | 碰撞、动画、InteractionArea、名牌/气泡 |
| DialogueUI | CanvasLayer 对话框 |

创建顺序建议：Player → NPC → DialogueUI → Main 组装。

### 15.5.2 玩家控制实现

`player.gd` 关键点：

- `add_to_group("player")`：NPC 靠组识别  
- `_physics_process`：读输入向量 → `velocity` → `move_and_slide`  
- `is_interacting`：对话中锁移动、播 idle、停走路音  
- 四向动画 / `flip_h` 兼容  

### 15.5.3 NPC 行为与交互

- `InteractionArea` 的 `body_entered/exited` 维护「附近玩家」  
- 提示「按 E 键交互」  
- 按 E → 信号通知 Main / UI，带上 `npc_id`  
- 可展示批量背景台词气泡  

**信号思维：** NPC 不直接 `get_node` 改 UI，而是发事件；Main 负责接线。

## 15.6 前后端通信实现

### 15.6.1 API 客户端封装

`api_client.gd` 把 HTTP 细节藏起来：

- 基址、超时、JSON  
- `request_dialogue` / `fetch_npc_status` / 可选好感查询  
- 信号：`dialogue_received` / `request_failed`  

**异步原则：** 请求发出后游戏继续跑帧；回包再刷 UI，避免卡死。

### 15.6.2 对话 UI 实现

职责：显示 NPC 名与职称、展示回复、接收输入、发送/关闭、发送中防连点。  
UI = 听筒；思考在后端。

### 15.6.3 主场景整合

推荐接线闭环：

```
E 交互 → 开 UI → ApiClient POST → 回写回复 → 关 UI 解锁移动
         ↘ 定时 GET /npcs/status → 刷新背景气泡
```

做到这一步，整章「可玩 Demo」闭环完成。

## 15.7 总结与展望

### 15.7.1 本章回顾

你带走的五块积木：

1. **分层架构**：渲染 / API / Agent / 外部服务  
2. **NPC 智能**：SimpleAgent + Prompt + 记忆  
3. **关系系统**：五级好感驱动语气  
4. **Godot 工程**：场景实例化 + 信号  
5. **HTTP 编排**：异步客户端与可观测日志  

### 15.7.2 扩展方向（选题菜单）

1. 多人在线（WebSocket + 每玩家好感）  
2. 任务系统（好感门槛解锁）  
3. NPC 互聊（后台自动对话）  
4. 更细情感状态  
5. 动态事件（会议 / 派对）  
6. 多场景大地图  
7. 个性化偏好学习  

### 15.7.3 思考与展望

AI NPC 的三座山：**成本、延迟、内容可控**。对策方向包括批量/缓存、打字机动画与预生成、端侧小模型、Prompt 与过滤护栏。  

下一阶段进入毕业设计：用单智能体与多智能体构造通用 Agent——舞台交给你。
