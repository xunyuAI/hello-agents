# 第八章 记忆与检索

第七章我们已经搭好了 HelloAgents 的基础骨架：Agent 范式、工具系统、LLM 调用链路。但如果你现在直接拿 `SimpleAgent` 去跑一个连续对话的学习助手，很快会撞墙——它**记不住你上一轮说过什么**，也**读不进你本地的 PDF 文档**。

这一章要补上的，就是智能体走向“真正可用”的两块拼图：

- **记忆系统（Memory）**：让 Agent 像人一样，能记住对话、偏好、经历，还能选择性遗忘和整理。
- **检索增强生成（RAG）**：让 Agent 不只靠训练数据“硬编”，而是先去外部知识库里查资料，再基于证据回答。

你可以把这一章理解成：**给 Agent 装上“短期便签 + 长期笔记本 + 外部图书馆”**。

---

## 读这一章之前，先建立心智模型

### 一个生活比喻

想象你在帮朋友复习一门课：

| 人类能力 | Agent 对应 | 本章组件 |
|---------|-----------|---------|
| 脑子里正在想的几句话 | 工作记忆 | `WorkingMemory` |
| “上周三我们讨论过 Transformer” | 情景记忆 | `EpisodicMemory` |
| “巴黎是法国首都”这类知识 | 语义记忆 | `SemanticMemory` |
| 记得某张课件截图长什么样 | 感知记忆 | `PerceptualMemory` |
| 翻开教材查定义 | 外部知识检索 | `RAGTool` |

LLM 本身像一位**记忆力极差、知识截止于训练日期**的顾问。Memory 和 RAG 不是替代 LLM，而是**补足它的两个根本短板**：无状态（每轮对话从零开始）和静态知识（不知道你的私有文档）。

### 几个关键词，先抓牢

- **Memory**：存“交互过程中产生的信息”——你是谁、你问过什么、你记下的笔记。
- **RAG（Retrieval-Augmented Generation）**：检索 + 增强 + 生成；先查文档，再把查到的片段塞进 Prompt，最后让 LLM 回答。
- **向量 / 嵌入（Embedding）**：把文字变成一串数字（向量），语义相近的文字，向量距离也近——这是“按意思搜”而不是“按字面搜”的基础。
- **分块（Chunking）**：长文档切成小段再入库，否则既塞不进上下文，检索也不精准。
- **consolidate（整合）**：把重要的短期记忆“升级”成长期记忆，类似睡前把便签整理进笔记本。
- **forget（遗忘）**：不是 bug，是特性——记忆太多会拖慢检索、浪费存储，要有策略地删。

### 建议怎么读

1. **先跑 30 秒体验**（8.1.4）：确认 `.env`、Qdrant、Neo4j、Embedding 配好，看到 `[OK]` 日志再往下读。
2. **对照图 8.2–8.4**：架构图和工作流程图是本章的“总线”，代码细节看不懂时回到图。
3. **Memory 和 RAG 分开学，再合起来**：8.2 专注记忆生命周期，8.3 专注文档入库与检索，8.4 看二者如何协作。
4. **评分公式不用背**：理解“相似度 + 时间 + 重要性”三个因素如何加权即可。
5. **习题当复盘**：8.5 末尾有 5 大题的导读要点，做完一遍比单纯读两遍更有效。

## 8.1 从认知科学到智能体记忆

### 8.1.1 人类记忆系统的启发

在写一行记忆代码之前，先问：人脑是怎么存信息的？认知心理学给出了一个经典分层模型（Atkinson-Shiffrin 模型），如图 8.1。

<div align="center">
  <img src="https://raw.githubusercontent.com/datawhalechina/Hello-Agents/main/docs/images/8-figures/8-1.png" alt="人类记忆系统结构图" width="85%"/>
  <p>图 8.1 人类记忆系统的层次结构</p>
</div>

**新手可以这样记：**

1. **感觉记忆**：极短（0.5–3 秒），容量巨大——相当于摄像头连续拍帧，大部分立刻丢弃。
2. **工作记忆**：短（约 15–30 秒），容量有限（经典说法是 7±2 项）——你心算时脑子里转的那几个数。
3. **长期记忆**：可持续终生，容量近乎无限，又分：
   - **程序性记忆**：技能与习惯（骑车、打字）。
   - **陈述性记忆**：
     - **语义记忆**：事实与概念（“Python 是解释型语言”）。
     - **情景记忆**：个人经历与事件（“昨天开会讨论了什么”）。

HelloAgents 的四类记忆（Working / Episodic / Semantic / Perceptual）并不是 1:1 复制人脑，而是**借认知科学的结构来组织工程模块**——每种记忆有不同的存储后端、生命周期和检索策略，避免“所有信息扔进同一个数据库”的混乱。

### 8.1.2 为何智能体需要 Memory 与 RAG

#### 局限一：无状态 → 对话遗忘

当前 LLM 在 API 层面通常是**无状态**的：每次 `run()` 如果不带历史消息，模型就不知道上一轮说了什么。

```python
# 第七章的 Agent 使用方式——没有记忆时的问题
from hello_agents import SimpleAgent, HelloAgentsLLM

agent = SimpleAgent(name="学习助手", llm=HelloAgentsLLM())

# 第一次对话
response1 = agent.run("我叫张三，正在学习 Python，目前掌握了基础语法")
print(response1)  # "很好！Python 基础语法是编程的重要基础..."

# 第二次对话（新的会话，没有历史）
response2 = agent.run("你还记得我的学习进度吗？")
print(response2)  # "抱歉，我不知道您的学习进度..."
```

**这会带来四个实际问题：**

| 问题 | 表现 | Memory 如何解决 |
|-----|------|----------------|
| 上下文丢失 | 长对话早期信息被窗口截断 | 工作记忆 + 整合到长期记忆 |
| 个性化缺失 | 不记得用户偏好 | 语义记忆存用户画像 |
| 学习能力受限 | 无法从成败经验改进 | 情景记忆记录事件 |
| 一致性问题 | 前后回答矛盾 | 检索历史记忆作为上下文 |

> **注意**：即使你在应用层手动拼接 `messages` 历史，也只是“把聊天记录塞回窗口”，并没有结构化存储、语义检索、遗忘与整合。Memory 系统提供的是**可管理、可检索、可生命周期控制**的记忆层。

#### 局限二：静态知识 → 需要 RAG

LLM 的知识来自训练语料，有**截止日期**，也不包含你的私有 PDF、内部 Wiki、产品手册。

| 问题 | RAG 如何解决 |
|-----|-------------|
| 知识时效性 | 外部知识库可随时更新 |
| 专业领域深度 | 导入领域文档构建专属库 |
| 事实准确性 | 回答基于检索片段，可附来源 |
| 可解释性 | 展示引用段落与相似度分数 |

RAG 的核心思想：**生成之前先检索**——从外部知识库找出最相关片段，作为上下文提供给 LLM，减少“凭空编造”。

#### Memory 与 RAG 的分工（新手易混点）

| 维度 | Memory | RAG |
|-----|--------|-----|
| 存什么 | 交互过程产生的信息（对话、笔记、事件） | 用户提供的文档/知识库 |
| 谁产生数据 | Agent 与用户互动 | 用户上传 PDF、文本等 |
| 典型问题 | “我上次学到哪了？” | “这份 PDF 里 Transformer 怎么定义的？” |
| 工具 | `MemoryTool` | `RAGTool` |

两者可以联动：RAG 检索到的重要结论，可以 `add` 进语义记忆；用户提问记录进情景记忆——8.4 案例会完整演示。

#### 记忆系统四层架构

```
HelloAgents 记忆系统
├── 基础设施层 (Infrastructure Layer)
│   ├── MemoryManager   — 统一调度协调
│   ├── MemoryItem      — 标准化记忆数据结构
│   ├── MemoryConfig    — 系统参数配置
│   └── BaseMemory      — 通用接口定义
├── 记忆类型层 (Memory Types Layer)
│   ├── WorkingMemory   — 工作记忆（临时，TTL）
│   ├── EpisodicMemory  — 情景记忆（事件序列）
│   ├── SemanticMemory  — 语义记忆（知识图谱）
│   └── PerceptualMemory— 感知记忆（多模态）
├── 存储后端层 (Storage Backend Layer)
│   ├── QdrantVectorStore    — 向量检索
│   ├── Neo4jGraphStore      — 知识图谱
│   └── SQLiteDocumentStore  — 结构化持久化
└── 嵌入服务层 (Embedding Service Layer)
    ├── DashScopeEmbedding       — 通义千问（云端）
    ├── LocalTransformerEmbedding— 本地模型（离线）
    └── TFIDFEmbedding           — 轻量兜底
```

**读架构图的技巧：** 从上往下是“业务抽象 → 具体存储”；从左到右四种记忆类型**按需启用**（默认不强制开 Perceptual，节省资源）。

#### RAG 系统分层

```
HelloAgents RAG 系统
├── 文档处理层 — DocumentProcessor、MarkItDown 转换、Pipeline
├── 嵌入表示层 — 复用记忆系统的统一嵌入接口
├── 向量存储层 — Qdrant（命名空间隔离）
└── 智能问答层 — MQE / HyDE 高级检索 + LLM 生成
```

RAG 在设计上被定义为**一条 Pipeline + 一个 Tool**，而不是像 Memory 那样多层类型模块——因为 RAG 的输入是“文档”，输出是“检索结果/答案”，流程相对线性。

## 8.2 记忆系统：让智能体拥有记忆

### 8.2.1 记忆系统的工作流程

认知科学里，记忆形成经历五个阶段——HelloAgents 将其映射为具体工程操作：

| 认知阶段 | 含义 | HelloAgents 对应 |

| 编码 Encoding | 感知信息转为可存储形式 | `add` 操作，写入 MemoryItem |

#### 四种记忆模块，各自干什么

**1. 工作记忆（Working Memory）——“当前对话的桌面”**

- 存当前会话上下文，默认容量约 50 条。
- 纯内存 + TTL，会话结束或超时自动清理。
- 类比：你写字时压在稿纸上的几张便签。

**2. 情景记忆（Episodic Memory）——“日记本”**

- 存具体事件：何时、何地、发生了什么。
- SQLite + Qdrant 混合存储，支持按时间/会话回顾。
- 类比：“2024 年 3 月 15 日完成了第一个 Python 项目”。

**3. 语义记忆（Semantic Memory）——“知识库 + 概念网络”**

- 存抽象知识、用户偏好、规则。
- Qdrant 向量 + Neo4j 知识图谱，支持关系推理。
- 类比：“用户喜欢简洁代码风格”“Python 是解释型语言”。

**4. 感知记忆（Perceptual Memory）——“多媒体相册”**

- 存图像、音频等多模态数据，支持跨模态检索。
- 按模态分离向量集合，避免维度不匹配。
- 默认不启用，需要时通过 `memory_types` 打开。

### 8.2.2 快速体验：30 秒上手记忆功能

```python
from hello_agents import SimpleAgent, HelloAgentsLLM, ToolRegistry
from hello_agents.tools import MemoryTool

llm = HelloAgentsLLM()
agent = SimpleAgent(name="记忆助手", llm=llm)

memory_tool = MemoryTool(user_id="user123")
tool_registry = ToolRegistry()
tool_registry.register_tool(memory_tool)
agent.tool_registry = tool_registry

print("=== 添加多个记忆 ===")

result1 = memory_tool.execute(
    "add",
    content="用户张三是一名 Python 开发者，专注于机器学习和数据分析",
    memory_type="semantic",
    importance=0.8
)
print(f"记忆1: {result1}")

result2 = memory_tool.execute(
    "add",
    content="李四是前端工程师，擅长 React 和 Vue.js 开发",
    memory_type="semantic",
    importance=0.7
)
print(f"记忆2: {result2}")

result3 = memory_tool.execute(
    "add",
    content="王五是产品经理，负责用户体验设计和需求分析",
    memory_type="semantic",
    importance=0.6
)
print(f"记忆3: {result3}")

print("\n=== 搜索特定记忆 ===")
print("🔍 搜索 '前端工程师':")
```

### 8.2.3 MemoryTool 详解

MemoryTool 是 Agent 与记忆系统之间的**统一入口**，设计模式是“统一 execute，按 action 分发”。

#### 操作 1：`add` —— 编码与存储

```python
def _add_memory(
    self,
    content: str = "",
    memory_type: str = "working",
    importance: float = 0.5,
    file_path: str = None,
    modality: str = None,
    **metadata
) -> str:
    """添加记忆"""
    # 自动管理 session_id
    if self.current_session_id is None:
        self.current_session_id = f"session_{datetime.now().strftime('%Y%m%d_%H%M%S')}"

    # 感知记忆：支持文件路径
    if memory_type == "perceptual" and file_path:
        inferred = modality or self._infer_modality(file_path)
        metadata.setdefault("modality", inferred)
        metadata.setdefault("raw_data", file_path)

    metadata.update({
        "session_id": self.current_session_id,
        "timestamp": datetime.now().isoformat()
    })

    memory_id = self.memory_manager.add_memory(
        content=content,
        memory_type=memory_type,
        importance=importance,
        metadata=metadata,
        auto_classify=False
    )
    return f"✅ 记忆已添加 (ID: {memory_id[:8]}...)"
```

### 8.2.5 四种记忆类型与评分公式对照

这一节是第八章的“硬核干货”。四种记忆的检索都遵循同一哲学：**语义相关度 + 时间因素 + 重要性权重**，但各项权重不同——因为它们服务的场景不同。

#### 总览对照表

| 记忆类型 | 存储方案 | 检索策略 | 评分公式（最终得分） |
|---------|---------|---------|---------------------|
| Working | 纯内存 + TTL | TF-IDF + 关键词混合 | `(相似度 × 时间衰减) × (0.8 + 重要性 × 0.4)` |
| Episodic | SQLite + Qdrant | 结构化过滤 + 向量 | `(向量×0.8 + 近因×0.2) × (0.8 + 重要性×0.4)` |
| Semantic | Qdrant + Neo4j | 向量 + 图混合 | `(向量×0.7 + 图×0.3) × (0.8 + 重要性×0.4)` |
| Perceptual | 分模态 Qdrant | 同模态向量 + 融合 | `(向量×0.8 + 近因×0.2) × (0.8 + 重要性×0.4)` |

**重要性权重范围：** `0.8 + importance × 0.4`，当 importance=0 时为 0.8，为 1 时为 1.2——避免重要性完全压倒语义相似度。

---

#### （1）工作记忆 WorkingMemory

```python
class WorkingMemory:
    """特点：
    - 容量有限（默认 50 条）+ TTL 自动清理
    - 纯内存存储，访问极快
    - 混合检索：TF-IDF 向量化 + 关键词匹配
    """
    def retrieve(self, query: str, limit: int = 5, **kwargs) -> List[MemoryItem]:
        vector_scores = self._try_tfidf_search(query)
        for memory in self.memories:
            vector_score = vector_scores.get(memory.id, 0.0)
            keyword_score = self._calculate_keyword_score(query, memory.content)
            base_relevance = vector_score * 0.7 + keyword_score * 0.3 if vector_score > 0 else keyword_score
            time_decay = self._calculate_time_decay(memory.timestamp)
            importance_weight = 0.8 + (memory.importance * 0.4)
            final_score = base_relevance * time_decay * importance_weight
```

**为什么工作记忆用 TF-IDF 而不是大模型 Embedding？** 工作记忆强调**速度**和**轻量**，条目少、生命周期短，TF-IDF 足够且无需 API 调用。

**新手理解：** 便签纸上的内容，越新越容易被翻到；不太重要的便签会先被扔掉（容量满时 `_remove_lowest_priority_memory`）。

#### （2）情景记忆 EpisodicMemory

```python
def _calculate_episode_score(self, hit) -> float:
    vec_score = float(hit.get("score", 0.0))
    recency_score = self._calculate_recency(hit["metadata"]["timestamp"])
    importance = hit["metadata"].get("importance", 0.5)
    base_relevance = vec_score * 0.8 + recency_score * 0.2
    importance_weight = 0.8 + (importance * 0.4)
    return base_relevance * importance_weight
```

**为什么情景记忆强调时间近因性（0.2）？** 情景记忆存的是“事件”。问“我最近在学什么”，你更关心**最近**发生的事，而不是三年前的某次对话——所以近因性占 20% 权重。

检索流程：结构化预过滤（时间范围、session_id）→ 向量语义检索 → 综合评分排序。

**时间衰减（指数模型）：**

```python
def _calculate_recency_score(self, timestamp: str) -> float:
    age_hours = (current_time - memory_time).total_seconds() / 3600
    decay_factor = 0.1
    recency_score = math.exp(-decay_factor * age_hours / 24)
    return max(0.1, recency_score)  # 最低 0.1
```

24 小时内高分，之后指数衰减——模拟遗忘曲线。

## 8.3 RAG 系统：知识检索增强

### 8.3.1 RAG 的基础知识

#### （1）什么是 RAG？

**检索增强生成（RAG）** = 检索 + 增强 + 生成：

1. **检索**：从知识库查相关文档片段。
2. **增强**：把片段注入 Prompt，给 LLM 当“开卷资料”。
3. **生成**：LLM 基于资料回答，而非纯靠参数记忆。

#### （2）基本工作流程

**两阶段：**

| 阶段 | 步骤 | 产出 |
|-----|------|------|
| 数据准备（离线/入库） | 提取 → 分割 → 向量化 → 入库 | 可检索的向量索引 |
| 应用（在线/问答） | 提问 → 检索 → 注入 Prompt → 生成 | 有依据的答案 |

#### （3）三代演进

| 阶段 | 时间 | 检索 | 生成 | 特点 |
|-----|------|------|------|------|
| 朴素 RAG | 2020–2021 | TF-IDF / BM25 关键词 | 检索结果直接拼接 | 简单，不懂语义 |
| 高级 RAG | 2022–2023 | 稠密向量语义检索 | 查询重写、分块、重排序 | 召回率大幅提升 |
| 模块化 RAG | 2023–至今 | 混合检索、MQE、HyDE | CoT、自我反思 | 可插拔、可组合 |

HelloAgents 的 RAG 实现定位在**高级 RAG → 模块化 RAG**之间：Markdown 结构化分块 + 向量检索 + MQE/HyDE 扩展。

| `chunk_size` | 800–1200 tokens | 检索不精准 | 上下文碎片化 |
| `chunk_overlap` | 100–200 tokens | 存储冗余 | 边界丢信息 |

| 优先级 | 方案 | 优点 | 缺点 |
|-------|------|------|------|
| 1 | DashScope（百炼 API） | 中文效果好、免本地 GPU | 需 API、有成本 |
| 2 | Local Transformer（如 all-MiniLM-L6-v2） | 离线、免费 | 需下载模型、中文弱于云端 |

### 8.3.5 高级检索策略

用户提问的表述，和文档里的写法往往不一致——**MQE** 和 **HyDE** 就是为解决“查不到”的问题。

#### （1）多查询扩展 MQE

**思想：** 一个问题多种问法，并行检索再合并。

```python

    """LLM 生成 n 个语义等价/互补的查询变体"""
    # "如何学 Python" → "Python 入门教程" / "Python 学习方法" / ...
```

**适合：** 模糊查询、口语化提问、召回率优先的场景。

#### （2）假设文档嵌入 HyDE

**思想：** 用答案找答案——先让 LLM 写一段“假设性答案”，再用这段文字的向量去检索。

```python
def _prompt_hyde(query: str) -> Optional[str]:
    """生成假设性答案段落，用于向量检索"""
```

**为什么有效？** 问题和答案在向量空间里分布不同（疑问句 vs 陈述句），假设答案更接近真实文档的表述风格。

**适合：** 专业领域术语密集的查询。

#### （3）统一扩展检索框架

```python
def search_vectors_expanded(
    query, top_k=8,
    enable_mqe=False, mqe_expansions=2,

):
    expansions = [query]

    if enable_hyde:

        if hyde_text:
            expansions.append(hyde_text)
    # 对每个扩展查询检索 → 去重 → 按分数 merge → 返回 top_k
```

**选型建议：**

| 场景 | 建议 |
|-----|------|
| 一般文档问答 | 基础检索 或 仅 MQE |
| 专业术语密集 | MQE + HyDE |
| 性能敏感 / 低成本 | 仅基础检索 |
| 8.4 学习助手默认 | `enable_mqe=True, enable_hyde=True` |

### 8.4.2 核心助手类 PDFLearningAssistant

#### （1）初始化：用户隔离 + 命名空间

```python
class PDFLearningAssistant:
    def __init__(self, user_id: str = "default_user"):
        self.user_id = user_id
        self.session_id = f"session_{datetime.now().strftime('%Y%m%d_%H%M%S')}"

        self.memory_tool = MemoryTool(user_id=user_id)
        self.rag_tool = RAGTool(rag_namespace=f"pdf_{user_id}")

        self.stats = {
            "session_start": datetime.now(),
            "documents_loaded": 0,
            "questions_asked": 0,
            "concepts_learned": 0
        }
        self.current_document = None
```

**设计要点：**

- `user_id` → Memory 数据隔离（不同用户不同记忆空间）。
- `rag_namespace=f"pdf_{user_id}"` → RAG 向量库隔离（用户 A 的 PDF 不会被用户 B 搜到）。
- `session_id` → 单次学习会话追踪，便于回顾和报告。

#### （2）加载 PDF：RAG 入库 + 情景记忆双写

```python
def load_document(self, pdf_path: str) -> Dict[str, Any]:
    result = self.rag_tool.execute(
        "add_document",
        file_path=pdf_path,
        chunk_size=1000,
        chunk_overlap=200
    )
    if result.get("success", False):
        self.current_document = os.path.basename(pdf_path)
        self.stats["documents_loaded"] += 1

        # 双写：记录“加载文档”这一事件
        self.memory_tool.execute(
            "add",
            content=f"加载了文档《{self.current_document}》",
            memory_type="episodic",
            importance=0.9,
            event_type="document_loaded",
            session_id=self.session_id
        )
        return {"success": True, "message": "加载成功！", ...}
```

**为什么用情景记忆而不是语义记忆？** “某时某刻加载了某 PDF”是一个**具体事件**，带时间线，适合 episodic；文档里的**知识点**才适合 semantic（通过问答和笔记写入）。

### 8.4.3 智能问答：`ask` 的双写记忆

```python
def ask(self, question: str, use_advanced_search: bool = True) -> str:
    if not self.current_document:
        return "⚠️ 请先加载文档！"

    # 1. 工作记忆：当前问题的临时上下文
    self.memory_tool.execute(
        "add",
        content=f"提问: {question}",
        memory_type="working",
        importance=0.6,
        session_id=self.session_id
    )

    # 2. RAG 问答（MQE + HyDE）
    answer = self.rag_tool.execute(
        "ask",
        question=question,
        limit=5,
        enable_advanced_search=use_advanced_search,
        enable_mqe=use_advanced_search,
        enable_hyde=use_advanced_search
    )

    # 3. 情景记忆：记录这次 QA 交互
    self.memory_tool.execute(
        "add",
        content=f"关于'{question}'的学习",
        memory_type="episodic",
        importance=0.7,
        event_type="qa_interaction",
        session_id=self.session_id
    )

    self.stats["questions_asked"] += 1
    return answer
```

**双写逻辑图：**

```
用户提问
  ├─→ working memory（当下上下文，TTL 后会清理）
  ├─→ RAG ask（查 PDF 知识库，返回答案+来源）
  └─→ episodic memory（学习历程，长期可查）
```

RAG 内部 `ask` 流程：MQE 扩展查询 → HyDE 假设文档 → 向量检索 → 合并上下文 → LLM 生成。

### 8.4.4 其他核心功能

```python
def add_note(self, content: str, concept: Optional[str] = None):
    """笔记 → 语义记忆（概念级知识）"""
    self.memory_tool.execute(
        "add", content=content, memory_type="semantic",
        importance=0.8, concept=concept or "general",
        session_id=self.session_id
    )
    self.stats["concepts_learned"] += 1

def recall(self, query: str, limit: int = 5) -> str:
    """回顾学习历程 → 搜索记忆"""
    return self.memory_tool.execute("search", query=query, limit=limit)

def get_stats(self) -> Dict[str, Any]:
    duration = (datetime.now() - self.stats["session_start"]).total_seconds()
    return {
        "会话时长": f"{duration:.0f}秒",
        "加载文档": self.stats["documents_loaded"],
        "提问次数": self.stats["questions_asked"],
        "学习笔记": self.stats["concepts_learned"],
        "当前文档": self.current_document or "未加载"
    }

def generate_report(self, save_to_file: bool = True) -> Dict[str, Any]:
    memory_summary = self.memory_tool.execute("summary", limit=10)
    rag_stats = self.rag_tool.execute("stats")
    report = {
        "session_info": {...},
        "learning_metrics": {...},
        "memory_summary": memory_summary,
        "rag_status": rag_stats
    }
    if save_to_file:
        report_file = f"learning_report_{self.session_id}.json"
        with open(report_file, 'w', encoding='utf-8') as f:
            json.dump(report, f, ensure_ascii=False, indent=2, default=str)
    return report
```

| 方法 | 记忆类型 | 作用 |
|-----|---------|------|
| `add_note` | semantic | 用户主动沉淀的概念笔记 |
| `recall` | 跨类型 search | “我之前学过什么” |
| `get_stats` | — | 会话级统计 |
| `generate_report` | summary + stats | 导出 JSON 学习报告 |

### 8.5.2 三个常见误解，顺手纠正

1. **“有了 RAG 就不需要 Memory 了”** — 错。RAG 管外部文档，Memory 管交互历史；问“我上次学到哪”只有 Memory 能答。

## 习题导读（5 大题要点）

> 原书习题无标准答案，重在培养综合理解。下面是每题的**思考方向与动手建议**，不必抄全题面。

### 习题 1：四种记忆类型与评分机制

**子题 A — 对比情景 vs 语义记忆的评分权重**

- 情景记忆：**时间近因 0.2** — 因为 episodic 存的是“什么时候发生了什么”，回顾时“最近的事”更相关。
- 语义记忆：**图检索 0.3** — 因为 semantic 存概念关系，向量 alone 不够，需要 Neo4j 做多跳关联。
- 写答案时建议画一张小表（见 8.2.5 对照表），并各举一个查询例子。

**子题 B — 个人健康管理助手如何组合四种记忆**

| 记忆类型 | 应用场景示例 |
|---------|-------------|
| Working | 当前对话：“刚说的今日步数 8000” |
| Episodic | “3 月 1 日跑步 5 公里”“上周体检报告已上传” |
| Semantic | “用户对乳糖不耐受”“BMI 正常范围知识” |
| Perceptual | 食物照片、运动手环截图 |

**子题 C — 何时 consolidate？自动触发条件设计**

- 工作记忆 TTL 到期**之前**，对 `importance >= 0.7` 的条目自动 consolidate。
- 可额外触发：会话结束 hook、每日定时任务、工作记忆使用率 > 80%。
- 思考：什么不该 consolidate？（一次性闲聊、敏感临时信息）

---

### 习题 2：RAG 分块与检索策略

**子题 A — 无标题结构文档的分块优化**

- 小说/法律条文：用语义边界（段落相似度突变、句号+主题切换）或滑动窗口。
- 可尝试：`RecursiveCharacterTextSplitter` 思路，或按固定字符数 + overlap。
- **动手**：拿一章小说文本，对比“按标题分”vs“按语义分”的 chunk 质量。

**子题 B — MQE / HyDE / 基础检索对比实验**

- 选一个真实场景（如 Happy-LLM PDF 问答），准备 10 个问题。
- 分别跑：`enable_mqe=False, enable_hyde=False` / 仅 MQE / MQE+HyDE。
- 记录：召回片段是否相关、答案是否引用正确、延迟与 API 成本。
- 结论模板：基础检索适合精确关键词；MQE 适合口语化；HyDE 适合专业术语。

**子题 C — 三种 Embedding 方案选型**

| 维度 | 百炼 API | 本地 Transformer | TF-IDF |
|-----|---------|-----------------|--------|
| 准确性 | 高（中文） | 中 | 低 |
| 速度 | 依赖网络 | 中 | 快 |
| 成本 | 按量付费 | 免费（GPU/CPU） | 免费 |
| 离线 | 否 | 是 | 是 |

选型建议：生产中文 RAG → 百炼；离线原型 → 本地；单元测试/兜底 → TF-IDF。

---

### 习题 3：遗忘机制扩展实践

**子题 A — 智能遗忘策略**

- 设计加权分：`forget_score = w1*(1-importance) + w2*age_normalized + w3*(1-access_frequency)`。
- 分数超过阈值则遗忘；权重可配置。
- **动手**：在 `forget` 基础上新增 `strategy="smart"`。

**子题 B — 记忆归档机制**

- 冷存储：长期未访问（如 90 天）但 importance 高的记忆 → 压缩存 S3/本地 archive 表。
- 恢复：检索 miss 时查 archive 索引，按需加载回热库。
- 与四种记忆集成：主要作用于 episodic 和 semantic；working 直接 TTL 清理。

**子题 C — 敏感数据彻底清除**

- 向量库删除 ID 不等于物理擦除；需调用 Qdrant delete + compact。
- Neo4j 需 DELETE 节点和关系，并考虑备份中的残留。
- Embedding 反查风险：即使删原文，向量仍可能被近似检索——高敏感场景避免向量化或加密后再入库。

---

### 习题 4：Memory + RAG 协作与多用户部署

**子题 A — 智能路由：何时 RAG vs Memory**

| 问题类型 | 优先 |
|---------|------|
| “PDF 里 Transformer 怎么定义？” | RAG |
| “我上次问了什么？” | Memory (episodic) |
| “我的笔记里关于 attention 写了啥？” | Memory (semantic) |
| 路由实现：先用 LLM 或规则分类 intent → 分发到对应 Tool |

**子题 B — 扩展学习报告**

- 用 episodic 时间线分析学习轨迹；用 semantic 笔记聚类找知识盲点。
- 推荐下一步：RAG 检索文档目录中未问过的章节。
- 需要：`search` + `summary` + 简单 LLM 分析 prompt。

**子题 C — 多用户数据隔离**

- Qdrant：`rag_namespace=user_{id}` + metadata filter `user_id`。
- Neo4j：节点属性 `user_id` 或子图隔离。
- 性能：按 namespace 分 collection；热用户缓存；批量检索限流。

---

### 习题 5：语义记忆与知识图谱

**子题 A — 自动实体关系提取的准确性**

- spaCy NER 对专业术语、新词覆盖不足；可能错误合并实体。
- 质量评估：抽样人工标注 precision/recall；低置信度关系不入图或标记待审核。

**子题 B — 图查询场景设计**

- 例：“与 Python 直接相关的概念有哪些，它们之间两跳内的关系？”
- Cypher：`MATCH (a:Entity {name:'Python'})-[*1..2]-(b) RETURN b`
- 纯向量检索难以保证结构完整性。

**子题 C — 混合 vs 纯向量**

- 图检索显著提升：**关系型/多跳/因果/层级**查询。
- 例：“哪些算法属于监督学习，且与决策树有关？”——向量找片段，图走 `IS_A` / `RELATED_TO` 边更准。
