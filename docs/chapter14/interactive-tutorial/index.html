14.1.1

传统研究的三个痛点

信息过载

  • 搜索返回海量链接
  • 逐个点开阅读成本高
  • 信号被噪声淹没

缺少结构

  • 信息碎片化
  • 难以形成系统视图
  • 不好写进报告

重复劳动

  • 每次都搜→读→总结
  • 流程无法沉淀
  • 难复用与审计
核心价值：1–2 小时压缩到 5–10 分钟；系统化避免遗漏；全程可追溯；可扩展搜索源与分析工具。

同一主题两种路径

「Datawhale 是什么组织？」

传统方式

  • 搜出 10–20 个链接
  • 人工点开、记笔记
  • 结果碎片、缺系统结构

TODO 驱动

  • TODO1 基本信息 · TODO2 主要项目
  • TODO3 社区文化 · TODO4 影响力
  • 每 TODO：搜→总结→引用来源
  • 最后结构化报告 + 参考文献
优势：可分解 · 可追溯 · 少遗漏 · 可增减子任务

Planner · Executor · Writer

完整系统的三个齿轮

规划器

TODO Planner

理解主题关键面，拆出 3–5 个子任务，并为每个设计搜索 query（太少不全，太多冗余）。

执行器

Task Executor

搜索取资料、去冗余、保存引用；工程上由 Search + Summarizer + Note 协作完成。

生成器

Report Writer

按逻辑组织、合并重复、为观点挂来源，输出可读报告。

14.3.2 · 监听工具调用

为何要扩展 SimpleAgent？

深度研究需要：调试参数、全程日志、行为分析、前端实时进度。原 SimpleAgent 无监听钩子。

class ToolAwareSimpleAgent(SimpleAgent):
    def _execute_tool_call(self, tool_name, parameters):
        parsed = self._parse_parameters(parameters)
        result = super()._execute_tool_call(tool_name, parameters)
        if self._tool_call_listener:
            self._tool_call_listener({
                "agent_name": self.name, "tool_name": tool_name,
                "parsed_parameters": parsed, "result": result,
            })
        return result
像给每个扳手装上传感器：谁、何时、用了什么参数、结果如何——全部可观测。

def deduplicate_sources(sources):
    seen, out = set(), []
    for s in sources:
        if s["url"] not in seen:
            seen.add(s["url"]); out.append(s)
    return out

def limit_source_tokens(source, max_tokens=2000):
    # 粗估：1 token ≈ 4 chars
    max_chars = max_tokens * 4
    snip = source["snippet"]
    if len(snip) > max_chars: snip = snip[:max_chars] + "..."
    return {**source, "snippet": snip}
去重保质量；截断保上下文预算——否则 Summarizer Prompt 会被长摘要撑爆。

常见坑与对策

额外文本

前后有「好的，我将…」→ 正则抽 [...]

格式错误

字段缺失

校验必需键，拒绝脏任务
