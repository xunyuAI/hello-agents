# 第十四章 自动化深度研究智能体

在第十三章的旅行助手项目中，我们体验了如何把 HelloAgents 做成一个「能用的多智能体产品」。本章换赛道，聚焦**知识密集型应用**：构建一个能自动化执行深度研究任务的智能体助手。

旅行规划关心「路线是否可行」；深度研究关心「事实是否可核验」。信息会不断发散、事实会快速更新，用户还特别在意引用来源。所以本章要交付的不是「搜一下给个答案」，而是一份**可追溯的研究报告**。

为了做到这一点，系统需要三项核心能力：

1. **问题剖析**：把用户的开放主题拆成可检索的查询语句。
2. **多轮信息采集**：结合不同搜索 API 持续挖掘，并去重整合。
3. **反思与总结**：依据阶段结果识别知识空白，决定是否继续检索，并生成结构化总结。

> **怎么用这份学习版**  
> - 先建立心智模型，再对照原书代码细读。  
> - 建议配合 `interactive-tutorial/index.html`（Lab 14）翻页练习。  
> - 真正动手时，以仓库中的 `helloagents-deepresearch/` 为准。

## 读这一章之前，先建立心智模型

### 一个生活比喻

把深度研究助手想成「带助理的论文写作流程」：

| 人类做法 | 系统对应 |
|---------|---------|
| 先列提纲，决定要搞清哪几块 | TODO Planner |
| 按提纲逐节搜资料、做笔记 | Search + Summarizer + NoteTool |
| 最后统稿、加参考文献 | Report Writer |
| 写作过程随时告诉你进展 | SSE 推送到前端 |

传统搜索像「打开浏览器漫无目地点链接」；TODO 驱动像「先提纲后执行」，每一步都有输入输出，出了问题也知道卡在哪一环。

### 几个关键词，先抓牢

- **TODO 驱动研究**：把复杂主题拆成 3–5 个子任务，再规划→执行→整合。
- **子任务三字段**：`title`（标题）、`intent`（为何研究）、`query`（搜索查询，可用英文提高召回）。
- **三 Agent**：Planner / Summarizer / Report Writer，专而简单。
- **ToolAwareSimpleAgent**：在 `SimpleAgent` 上加工具调用监听，方便日志与前端进度。
- **服务层**：Planning / Summarization / Reporting / Search —— 连接 Agent 与工具的业务胶水。
- **SSE**：服务器单向推送事件流，用于实时进度，而不是整页刷新。

### 建议怎么读

1. **先跑通 5 分钟体验**（14.1.3），对 UI 与流程有体感。
2. **抓住图 14.1 / 14.2 / 14.5**：架构、数据流、TODO 流程是本章「总线」。
3. **按「范式 → Agent → 工具 → 服务 → 前端」顺序学**，不要一上来就陷入 Prompt 长文本。
4. **JSON 解析与搜索清洗是工程硬菜**：比「模型更聪明」更能决定系统稳不稳。

## 14.1 项目概述与架构设计

### 14.1.1 为什么需要深度研究助手

信息爆炸时代，了解新技术/概念/事件时，传统方式常见三个痛点：

1. **信息过载**：搜索结果成千上万，人工点开成本极高。  
2. **缺少结构**：即使找到相关内容，也往往是碎片，难成系统。  
3. **重复劳动**：每次都要「搜索→阅读→总结→整理」，流程无法沉淀。

深度研究助手的目标不是替代你思考，而是把重复劳动自动化，并留下可验证痕迹。

**核心价值（对照原书）：**

1. **省时间**：1–2 小时压缩到约 5–10 分钟（视主题与引擎而定）。  
2. **提质量**：系统化流程，减少遗漏。  
3. **可追溯**：保留搜索结果与来源，方便核验引用。  
4. **可扩展**：可继续加搜索引擎、数据源、分析工具。

### 14.1.2 技术架构概览

系统采用经典**前后端分离**，可记成四层：

| 层 | 技术 | 职责 |
|----|------|------|
| 前端 | Vue3 + TypeScript | 全屏模态、Markdown 可视化、进度展示 |
| 后端 | FastAPI | API / SSE：`/research/stream` |
| 智能体 | HelloAgents | 三 Agent + SearchTool + NoteTool |
| 外部服务 | 搜索引擎 + LLM | 取网页证据、生成规划/总结/报告 |

**一次请求怎么走（对应图 14.2）：**

1. 用户输入研究主题  
2. 前端经 SSE 连上 `/research/stream`  
3. FastAPI 创建研究状态  
4. **规划**：拆成约 3 个子任务（实践中常见 3–5）  
5. **执行**：逐任务 Search → Summarizer → NoteTool  
6. **报告**：Report Writer 整合  
7. SSE 推送进度与结果  
8. 前端更新任务状态、进度条、日志、报告  

**目录结构（记住「后端 services = 三阶段业务」）：**

```
helloagents-deepresearch/
├── backend/src/
│   ├── agent.py          # 协调器
│   ├── main.py           # FastAPI
│   ├── models.py / prompts.py / config.py
│   └── services/         # planner / summarizer / reporter / search
└── frontend/src/
    ├── App.vue
    ├── components/ResearchModal.vue
    └── composables/useResearch.ts
```

### 14.1.3 快速体验：5 分钟运行项目

## 14.2 TODO 驱动的研究范式

### 14.2.1 什么是 TODO 驱动的研究

一句话：**把「研究」这个模糊目标，变成「规划→执行→整合」的可调试流水线。**

传统路径：

```
主题 → 搜索引擎甩一堆链接 → 人逐个点开记笔记 → 碎片信息
```

TODO 驱动路径：

```
主题
 → 规划：TODO1 基本信息 / TODO2 项目 / TODO3 文化 / TODO4 影响力
 → 执行：每个 TODO 搜 → 总结 → 记来源
 → 整合：结构化报告 + 参考文献
```

**三大核心要素：**

1. **智能规划器（TODO Planner）**：拆出 3–5 个子任务，并为每个写好 query。  
2. **任务执行器（Task Executor）**：搜、提炼、去冗余、保引用（工程上由搜索服务 + 总结 Agent + 笔记工具协作）。  
3. **报告生成器（Report Writer）**：按逻辑组织、合并重复、挂来源。

整条流程是**线性**的，但每阶段 I/O 清晰——这正是易于理解与调试的原因（见图 14.5）。

### 14.2.2 三阶段研究流程

#### （1）规划 Planning

- **输入**：研究主题 + 当前日期（利于「最新」检索）。  
- **输出**：JSON 子任务列表，每项含 `title` / `intent` / `query`。  
- **质量标准**：覆盖全面、逻辑清晰、查询精准、数量适中。

示例（节选）：

```json
[
  {
    "title": "Datawhale的基本信息",
    "intent": "了解组织定位、成立时间、发展历程",
    "query": "Datawhale organization introduction history 2024"
  },
  {
    "title": "Datawhale的主要项目",
    "intent": "了解核心开源项目和教程",
    "query": "Datawhale projects tutorials open source 2024"
  }
]
```

#### （2）执行 Execution

对每个子任务：

1. `SearchTool.run({input, backend, mode:"structured", max_results:5})`  
2. 取出 title / url / snippet  
3. 调用总结 Agent 生成带 `[1][2]` 引用的 Markdown  
4. `NoteTool` 落盘  

同时向前端推送 `status` / `task` 等 SSE 事件，让用户看见「正在搜索… / 任务已完成」。

#### （3）报告 Reporting

- **输入**：全部子任务总结 + 主题  
- **输出**：Markdown 报告  

推荐骨架：

1. 标题  
2. 概述  
3. 各子任务详细分析  
4. 总结  
5. 参考文献  

报告 Agent 的职责是：按逻辑排序、消冗、统一格式、把引用汇总到参考文献区。

## 14.3 智能体系统设计

### 14.3.1 Agent 职责划分

第七章的 `SimpleAgent` 适合「单次问答 + 可选工具」。深度研究太长、太分叉，更适合**多智能体分工**（见表 14.1）。

#### Agent 1：TODO Planner（研究规划专家）

- **职责**：主题 → 3–5 个子任务 JSON。  
- **Prompt 关键点**：注入日期与主题；强调可搜索、有目标、彼此有逻辑；**只返回 JSON**。  
- **工程点**：`_extract_tasks` 用正则抽出 `[...]` 再 `json.loads`，因为模型常在 JSON 前后夹带自然语言。

#### Agent 2：Task Summarizer（任务总结专家）

- **职责**：搜索结果 → 结构化笔记。  
- **输出要求**：核心观点、关键数据（数字/日期/名称）、来源引用。  
- **实现提示**：先把 sources 格式化成 `[idx] title / URL / 摘要`，再填 Prompt。

#### Agent 3：Report Writer（报告撰写专家）

- **职责**：多份总结 → 一篇完整报告。  
- **结构钉在 Prompt 里**：标题 / 概述 / 分节 / 总结 / 参考文献，比事后「修报告」稳得多。

### 14.3.2 ToolAwareSimpleAgent 的设计

深度研究需要**可观测性**：

- 调试：谁调了什么工具、参数是什么  
- 日志：全过程可回放  
- 分析：行为模式  
- 进度：前端实时显示「正在搜索 / 正在写笔记」

`SimpleAgent` 没有监听钩子，因此扩展为 `ToolAwareSimpleAgent`：在 `_execute_tool_call` 里，调用父类执行后，若存在 `tool_call_listener`，就把 `agent_name / tool_name / parsed_parameters / result` 回调出去。

在 `DeepResearchAgent` 里，三个服务共用同一个 listener，把工具事件转成 SSE 推给前端——**同一套钩子，同时服务调试与产品体验**。

### 14.3.3 Agent 协作模式

三个 Agent 是**顺序协作**（图 14.6）：

1. **线性**：固定顺序  
2. **明确 I/O**：上一环输出 = 下一环输入  
3. **无并发**：同时只跑一个 Agent（易调试；后续若要加速，再考虑并行搜多个 TODO）

协调器伪代码心智模型：

```text
plan → emit tasks
for task in todo_list:
    search → summarize → record → emit task_completed
report → emit report
```

## 14.4 工具系统集成

### 14.4.1 SearchTool 扩展

第七章已有多源搜索思想；本章进一步扩展 DuckDuckGo、Perplexity、SearXNG，以及 Advanced（多引擎组合）等（见表 14.2）。

**配置化切换（不必改业务代码）：**

```python
# config.py 中 SearchAPI 枚举
# .env
SEARCH_API=tavily
```

统一返回字段记住：`results`、`backend`、可选 `answer`（Perplexity）、`notices`。

**两道清洗关卡（强烈建议动手实现时不要省）：**

1. **URL 去重**：同一链接只留一条。  
2. **Token/长度限制**：长 snippet 截断（教材用「约 4 字符 ≈ 1 token」粗估），避免撑爆 Summarizer 上下文。

### 14.4.2 NoteTool 使用

NoteTool 来自第九章：把研究中间产物落到磁盘。

**为什么必须持久化？**

- 研究可能中断，需要续跑  
- 需要审计「当时搜到了什么、怎么总结的」  
- 方便分析质量与效率  

典型目录：

```text
workspace/
├── notes/1.md 2.md 3.md ...
└── reports/final_report.md
```

笔记内容通常包含：任务意图与 query、原始搜索列表、总结正文。

### 14.4.3 ToolRegistry 工具管理

创建 Agent 前注册工具：

```python
registry = ToolRegistry()
registry.register_tool(search_tool)
registry.register_tool(note_tool)
agent = ToolAwareSimpleAgent(..., tool_registry=registry)
```

调用链路（图 14.7）：Agent 生成工具指令 → Registry 解析 → 查找工具 → `run` → 结果回传（并可被 listener 旁路观察）。

## 14.5 服务层实现

服务层是「业务逻辑容器」：Agent 负责语言智能，服务负责流程、校验、降级与缓存。

### 14.5.1 任务规划服务 PlanningService

四职责：

1. 构建规划 Prompt  
2. 调用 Planner Agent  
3. 提取 JSON  
4. 校验字段并生成 `TodoItem`  

**健壮解析策略：**

- 先正则找 JSON 数组  
- 再尝试整段 `json.loads`  
- 对每个 item 检查 `title/intent/query`  

可选：`evaluate_plan` 按数量、query 质量打分，给「过少/过多/查询过空」等建议。

### 14.5.2 总结服务 SummarizationService

把搜索结果格式化后交给 Summarizer，返回带引用的 Markdown。这一步决定报告「有没有证据感」。

### 14.5.3 报告生成服务 ReportingService

把 `List[(TodoItem, summary)]` 格式化为「任务 i + 意图 + 正文」块，再交给 Report Writer。Prompt 里把报告五段结构钉死。

### 14.5.4 搜索调度服务 SearchService

本章刻意**不让 SimpleAgent 直接摸搜索引擎**，而是经 SearchService：

1. 按配置选引擎  
2. 调 SearchTool  
3. 去重 + 截断  
4. 失败记日志并返回空列表（不拖垮全流程）  

进阶：用 `query + max_results + engine` 做 MD5 磁盘缓存，降成本、提重复实验速度（图 14.8）。

## 14.6 前端交互设计

### 14.6.1 全屏模态对话框 UI

优势：沉浸、层次清晰、易关闭（按钮 / Esc）、响应式。

四块区域（图 14.9）：

1. 顶栏：主题 + 关闭  
2. 进度区：规划 / 执行 / 报告百分比与文案  
3. 内容区：加载态或 Markdown HTML  
4. 底栏：状态文案  

实现上常见为 `ResearchModal.vue` + `marked` 渲染；小屏用媒体查询缩小边距，手机可全屏无圆角。

### 14.6.2 实时进度展示（SSE）

SSE = 服务器推送事件流（图 14.10）：

1. 客户端发起研究请求  
2. 服务器返回 `text/event-stream`  
3. 持续推送 `progress` / `plan` / `task_summary` / `report` / `error`  
4. 完成后关闭连接  

后端用 `StreamingResponse` + `yield "data: {...}\n\n"`；前端可用 `EventSource`（或 fetch 流）在 `useResearch.ts` 里更新进度与 Markdown。

### 14.6.3 研究结果可视化

```ts
marked.setOptions({ breaks: true, gfm: true })
const renderedHtml = marked(markdownContent.value)
```

参考文献建议按任务分组展示可点击链接，方便用户回源站核验——这是「深度研究」与「聊天回答」的产品分水岭。

## 14.7 本章小结

回顾六条主线：

1. **TODO 驱动范式**：规划 / 执行 / 报告，可控、可调试、可扩展。  
2. **三 Agent 协作**：Planner、Summarizer、Writer 专而清晰。  
3. **ToolAwareSimpleAgent**：工具调用可观测，服务调试与 SSE。  
4. **工具集成**：Search 多引擎配置化；Note 持久化；Registry 统一调度。  
5. **四服务层**：规划解析、总结、报告、搜索调度（含清洗/缓存/降级）。  
6. **前端产品化**：全屏模态 + SSE + Markdown 报告。

这些模式可迁移到竞品调研、学术综述、政策追踪等场景。下一章将进入赛博小镇，看游戏引擎场景下更复杂的多 Agent 交互。
